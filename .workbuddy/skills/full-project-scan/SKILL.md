# 全量项目扫描 (Full Project Scan)

当此技能激活时，你系统性地扫描整个项目，分析架构、依赖关系、代码质量，生成完整诊断报告。

## 扫描步骤

### 1. 项目结构分析
```
命令: file.list_directory + project.find_files
输出: 模块划分、文件分布、目录层次
```

### 2. 构建系统分析
```
读取: CMakeLists.txt（递归所有子目录）
分析: 依赖关系、编译选项、目标定义
检查: 是否有孤立文件、重复目标、缺失链接
```

### 3. 头文件依赖分析 (include graph)
```
方法: file.grep 搜索 #include
目的: 发现循环依赖、过度包含、缺失 include
```

### 4. 代码质量扫描
```
检查项:
- 函数长度（> 200 行标记）
- 文件长度（> 1000 行标记）
- 注释率（< 5% 标记）
- 魔法数字（硬编码常量）
- 未使用的 include（反复读取确认）
- Qt 信号槽连接检查（connect 语法）
```

### 5. 测试覆盖度分析
```
命令: project.find_files("tests/**/*.cpp")
对比: 源模块与测试模块的对应关系
```

### 6. API/技术债
```
检查: 
- 废弃的 Qt API
- C++11/14/17 特性使用是否合理
- 命名一致性
- 错误处理完整性
```

## 输出报告格式

```markdown
# CodeXX 项目诊断报告
生成时间: [timestamp]

## 模块结构
src/ (N 个子目录)
  ├── app/  → ApplicationController, AgentOrchestrator...
  ├── tools/ → 51+ 工具（7 个子模块）
  └── ...

## 关键指标
| 指标 | 数值 | 状态 |
|------|------|------|
| 源文件总数 | 120+ | — |
| 长函数(>200行) | X 个 | ⚠️ 关注 |
| 循环依赖 | Y 个 | ✅ 无 / ⚠️ 存在 |

## 测试覆盖
测试数: 65 | 源模块: N | 覆盖率: X%

## 建议
1. [优先级 P0] ...
2. [优先级 P1] ...
3. [优先级 P2] ...
```

## 规则
- 只读操作，不要修改任何文件
- 用 file.grep 做全量搜索，不要一个个文件打开
- 关注架构层面，不要纠结单个空格/缩进
- 最多搜索 200 个结果
