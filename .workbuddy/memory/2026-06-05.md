## V17.1 BugFix: DeepSeek API 图片格式修复 + 预览栏位置调整 (10:27)

### 问题1: 图片发送失败 `unknown variant image_url, expected text`

**根因**: DeepSeek API **不支持 OpenAI 的 `image_url` 格式**。DeepSeek 要求：

```json
// DeepSeek 格式（正确）:
{"type": "image", "image": {"data": "<raw_base64>", "format": "base64"}}

// OpenAI 格式（DeepSeek 不支持）:
{"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}
```

**两个改动**:
1. `"image_url"` → `"image"` 
2. `{"image_url": {"url": "..."}}` → `{"image": {"data": "...", "format": "base64"}}`
3. 剥离 `data:image/png;base64,` 前缀，只传原始 base64

**影响文件**: `src/services/OpenAICompatibleClient.cpp`（~10行改动）

### 问题2: 图片预览栏位置

**改动**: 图片预览栏从输入框**上方**（独立区域）移到输入框**内部下方**（与文字一起，属于同一个 composer 容器）

- `composerRow`（QTextEdit + 按钮）→ `m_imagePreviewBar`（紧凑图片卡片）
- 左右 margin 对齐（28px），视觉上属于输入区域的一部分

**影响文件**: `src/ui/MainWindow.cpp`（setupUi 布局调整）

### 测试

## BugFix: Agent 计划成功仍跑满 15 轮 OODA 循环 (12:12)

### 问题
用户报告："agent执行了一个指令成功生成了，但是她仍然跑了15步" 以及 "她说自己没成功"

**根因**: `ApplicationController.cpp` 中 3 处 `executePlanAndReportToChat()` 调用之后，**无条件**检查 `isAgentLoopActive()` 并进入 OODA 循环：
- 计划有 1 步 → 执行成功 → 报告执行结果 → 但 OODA 循环又跑了 15 轮
- 中间某轮 LLM 可能说"我做不到"（权限/路径问题），产生不一致认知

### 修复

```
旧：executePlanAndReportToChat(plan);  // 返回 void
    if (isAgentLoopActive())           // 无条件继续循环
        continueAgentLoop();           // 最多 15 轮

新：bool allSuccess = executePlanAndReportToChat(plan);  // 返回 bool
    if (allSuccess)                   // 全部成功 → 直接结束
        cancelAgentLoop() + "任务完成";
    else                              // 有失败 → 才进 OODA 尝试恢复
        continueAgentLoop();
```

### 改动文件
| 文件 | 改动 |
|---|---|
| `AgentOrchestrator.h` | `void executePlanAndReportToChat` → `bool executePlanAndReportToChat` |
| `AgentOrchestrator.cpp` | 返回值: `failCount == 0` |
| `ApplicationController.cpp` | 3 处调用改为条件分支 |

### 测试
65/65 ✅ + AgentLoopControllerTest ✅ + AgentLoopExecutionTest ✅
