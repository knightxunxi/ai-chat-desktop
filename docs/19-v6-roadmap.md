# V6 Roadmap

本文档用于规划 AI Chat Desktop 的 V6 阶段。V6 建立在 V5 的本地工具系统之上，目标是让应用具备有限、可确认、可记录的本地文件/系统交互能力，为后续 Agent 执行循环打基础。

执行状态：V6-TASK-001 至 V6-TASK-006 已完成。当前 V6 已实现受控文件工具、安全边界、文件交互测试、文件工具窗口 smoke test 和验收文档，当前测试数量为 22 个。

## 1. V6 目标

V6 重点解决四类问题：

- 本地交互：让用户可以通过应用读取指定文件、列出指定文件夹、保存输出和打开文件位置。
- 安全边界：所有文件/系统操作必须由用户主动触发，并且路径来源明确。
- 可追踪性：本地交互操作需要写入日志，失败时能定位原因。
- Agent 基础：为 V7 的“AI 选择工具 + 用户确认 + 执行工具”预留结构，但 V6 不做自动 Agent。

## 2. 技术类型

| 技术类型 | 用途 | 预期落点 |
| --- | --- | --- |
| Qt File API | 文件读取、保存、路径检查 | `QFile`、`QFileInfo`、`QDir` |
| Qt Dialog | 用户选择文件或目录 | `QFileDialog` |
| Qt Desktop Services | 打开文件或文件夹 | `QDesktopServices` |
| C++ 抽象接口 | 统一本地交互能力边界 | 文件工具或交互服务 |
| AppLogger | 记录本地交互操作 | 成功、失败、路径摘要 |
| CTest | 验证文件工具逻辑 | 临时目录、临时文件测试 |
| UI smoke test | 验证窗口基础交互 | 打开工具、选择模式、关闭 |
| 安全策略 | 限制高风险操作 | 禁止删除、执行脚本、后台自动操作 |

## 3. V6 范围

### 3.1 必做范围

- 输出本地交互安全设计。
- 实现读取用户指定文件。
- 实现列出用户指定文件夹。
- 实现保存工具输出或聊天文本到用户指定文件。
- 实现打开指定文件或文件夹。
- 所有操作有明确错误提示。
- 所有本地交互操作写入日志。
- 增加文件工具逻辑测试。
- 更新 README、学习文档和验收记录。

### 3.2 建议范围

- 文件大小限制。
- 文本编码处理。
- 二进制文件识别。
- 覆盖写入二次确认。
- 工具输出插入聊天输入框。
- 最近一次文件工具操作状态展示。

### 3.3 可选范围

- 文件摘要入口：读取文件后把内容插入聊天输入框，由用户手动发送给 AI。
- 会话导出路径记忆。
- 最近使用目录记忆。
- 更完整的 UI 自动化测试。

### 3.4 V6 暂不包含

- AI 自动选择工具。
- AI 自动执行文件操作。
- 删除文件。
- 移动文件。
- 覆盖文件时无确认写入。
- 任意脚本执行。
- 后台无人值守任务。
- 插件市场。
- 系统级全盘扫描。
- 云同步。
- macOS/Linux 迁移。

## 4. 推荐里程碑

### M1 本地交互安全设计

目标：

- 明确什么操作可以做，什么操作不能做。
- 明确路径来源、确认机制、日志策略和测试边界。

任务：

- 输出安全设计文档。
- 定义允许操作清单。
- 定义禁止操作清单。
- 定义文件大小和二进制文件处理策略。

验收标准：

- 文档说明路径来源、权限边界和失败处理。
- V6 后续实现都能按该文档判断是否越界。

### M2 文件交互基础服务

目标：

- 把文件读取、目录列出、保存、打开等操作从 UI 中抽出来。

任务：

- 新增文件交互服务或工具模块。
- 实现路径检查。
- 实现文本文件读取。
- 实现目录条目列出。
- 实现保存文本到指定文件。
- 实现打开文件或文件夹。

验收标准：

- 文件操作逻辑可以脱离 UI 单独测试。
- 失败时返回结构化错误。
- 操作日志可追踪。

### M3 文件工具窗口

目标：

- 让用户可以通过界面主动触发文件/目录操作。

任务：

- 在工具窗口或新增文件工具窗口中增加文件交互入口。
- 使用 `QFileDialog` 选择文件或目录。
- 展示读取或列出的结果。
- 支持复制结果。
- 支持插入聊天输入框。

验收标准：

- 读取文件、列出目录、保存文本、打开路径都能从 UI 触发。
- 用户不需要手动输入敏感路径。
- 工具输出不会自动发送给 AI。

### M4 安全和错误处理增强

目标：

- 降低误操作风险，提高失败定位能力。

任务：

- 加入文件大小限制。
- 二进制文件给出提示，不按文本读取。
- 覆盖保存时二次确认。
- 打开文件/文件夹前显示目标路径。
- 日志中记录操作类型和路径摘要。

验收标准：

- 大文件、二进制文件、无权限路径都有清晰提示。
- 覆盖写入不会静默发生。
- 日志不记录文件正文。

### M5 测试和验收

目标：

- 让文件交互能力可验证，避免只靠手工点击。

任务：

- 增加文件读取测试。
- 增加目录列出测试。
- 增加保存文本测试。
- 增加非法路径和大文件测试。
- 增加 UI smoke test 或手工验收清单。
- 输出 V6 验收记录。

验收标准：

- 本地构建通过。
- CTest 全部通过。
- 文档和实际能力一致。

## 6. 推荐执行顺序

```text
V6-TASK-001
-> V6-TASK-002
-> V6-TASK-003
-> V6-TASK-004
-> V6-TASK-005
-> V6-TASK-006
```

优先做安全设计和文件交互服务，因为 V6 的核心风险不是功能实现难度，而是权限、误操作和边界控制。

## 7. 风险点

- 文件路径如果允许直接输入，容易引入路径错误和误操作；优先使用选择框。
- 大文件读取可能导致 UI 卡顿；需要设置大小限制。
- 二进制文件不能按文本直接展示。
- 保存文件如果静默覆盖，会造成数据损失；必须确认。
- 日志不能记录文件正文或敏感内容。
- “打开文件”不是“执行脚本”；脚本执行不进入 V6。
- V6 不允许 AI 绕过用户确认自动操作电脑。

## 8. V6 验收标准

V6 完成时应满足：

- 本地交互安全设计完成。
- 可以读取用户选择的文本文件。
- 可以列出用户选择的文件夹。
- 可以保存文本到用户选择的文件。
- 可以打开用户确认的文件或文件夹。
- 文件工具输出可以复制或插入聊天输入框。
- 大文件、二进制文件、非法路径有清晰错误提示。
- 覆盖保存需要用户确认。
- 本地交互操作写入日志，且不记录文件正文。
- 新增测试通过。
- README、学习资料和验收记录同步更新。

## 9. V7-V10 后续方向

V6 完成后，推荐按风险递增进入后续阶段：

```text
V7：AI 拆解任务并建议工具
-> V8：默认工作目录文件 Agent
-> V9：受控命令执行
-> V10：操作记录和确认回放
-> V11：设备输入模拟
```

其中 V7 才考虑 Agent 执行循环雏形：

```text
用户目标
-> AI 拆解任务
-> AI 建议工具
-> 用户确认
-> 执行工具
-> 结果回传给 AI
-> 用户决定是否继续
```

V7 的前提是：

- V6 文件工具边界稳定。
- 所有本地操作都有日志。
- 高风险操作有确认。
- 用户可以中断流程。

更详细的命令执行、操作记录和设备输入模拟规划见 [Agent 与电脑交互后续规划](22-agent-automation-roadmap.md)。

## 10. 简历表达方向

V6 完成后可以考虑这样描述：

> 在 C++/Qt 桌面 AI 应用中设计受控本地交互工具，支持用户选择文件读取、目录列出、文本保存和路径打开；通过路径来源限制、文件大小校验、覆盖确认和日志记录降低误操作风险，并使用 CTest 覆盖文件工具核心逻辑。

这个表达重点是“受控交互、安全边界、可验证实现”，比直接写“做了 AI Agent”更准确。
