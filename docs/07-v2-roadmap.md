# V2 Roadmap

本文档用于规划 AI Chat Desktop 的 V2 版本。V2 的目标不是重新做一个产品，而是在 V1 已经能聊天、能保存配置和记录的基础上，提升架构质量、会话管理能力和日常使用体验。

## 1. V2 目标

V2 重点解决三类问题：

- 降低 `MainWindow` 的业务复杂度，让架构更接近企业项目。
- 完善多会话、停止生成、Markdown、复制等常见聊天体验。
- 为后续小工具、角色模板和多服务商扩展打基础。

## 2. V2 范围

### 2.1 必做范围

- 抽出 `ApplicationController`。
- 完善会话列表：加载多个会话、切换会话、新建会话、删除会话。
- 支持停止生成。
- 支持复制消息内容。
- 支持基础 Markdown 渲染。
- 增加更清楚的错误状态和日志。

### 2.2 可选范围

- 会话重命名。
- 会话搜索。
- 角色提示词模板。
- 导出聊天记录。
- 多服务商预设。

### 2.3 V2 暂不包含

- 云同步。
- 用户账号系统。
- 插件市场。
- 复杂权限管理。
- 完整自动更新系统。

## 3. 推荐里程碑

### M1 架构整理

目标：

- 把主窗口中的业务流程移动到控制层。

任务：

- 新增 `ApplicationController`。
- 主窗口只负责界面展示和用户交互事件。
- 控制层负责配置、会话、存储、API 调用和错误状态。
- 为控制层补充基础测试或可测试接口。

验收标准：

- `MainWindow` 不直接调用 `OpenAICompatibleClient`。
- `MainWindow` 不直接保存聊天记录。
- 发送消息、流式更新、失败处理仍然可用。

### M2 多会话管理

目标：

- 让左侧会话列表真正成为可用的会话管理入口。

任务：

- `ChatHistoryStorage` 支持加载所有会话摘要。
- 左侧列表展示多个会话。
- 点击会话可以切换。
- 新建会话后立即加入列表。
- 删除会话。
- 会话标题由第一条用户消息生成，后续支持手动重命名。

验收标准：

- 可以在多个会话之间切换。
- 切换后聊天内容和角色提示词正确恢复。
- 删除会话后数据库和 UI 状态一致。

### M3 生成控制和消息操作

目标：

- 补齐常见聊天软件的基础操作。

任务：

- 发送中将发送按钮切换为停止按钮。
- 点击停止可以取消当前网络请求。
- AI 已生成内容保留。
- 每条消息提供复制功能。
- 错误消息提供重试入口或清楚提示。

验收标准：

- 长回复生成过程中可以停止。
- 停止后 UI 恢复可输入状态。
- 复制用户消息和 AI 消息均可用。

### M4 Markdown 和展示体验

目标：

- 让 AI 回复更适合阅读代码、列表和标题。

任务：

- 支持基础 Markdown 渲染。
- 支持代码块等宽字体展示。
- 保持纯文本复制能力。
- 优化长文本滚动和换行。

验收标准：

- 标题、列表、代码块能基本正确展示。
- Markdown 渲染不影响流式更新稳定性。
- 长回复不会撑坏布局。

### M5 日志和错误诊断

目标：

- 出问题时更容易定位。

任务：

- 增加简单日志模块。
- 记录 API 请求开始、完成、失败，不记录 API Key。
- 网络错误、HTTP 错误、API 错误使用更明确的用户提示。
- 增加日志文件路径说明。

验收标准：

- 常见错误可以从 UI 提示和日志中定位。
- 日志不包含敏感 API Key。

## 4. V2 任务拆分

### V2-TASK-001 新增 ApplicationController

范围：

- 创建 `src/app/ApplicationController.h/.cpp`。
- 从 `MainWindow` 迁移发送消息、保存会话、加载会话、处理流式响应等流程。

验证：

- 构建通过。
- 现有 5 个测试通过。
- 手工发送消息仍可用。

### V2-TASK-002 调整 MainWindow 职责

范围：

- `MainWindow` 只保留 UI 初始化、控件事件转发和界面更新。
- 通过信号槽与 `ApplicationController` 通信。

验证：

- 设置、发送、新建会话、角色提示词入口仍可用。

### V2-TASK-003 扩展 ChatHistoryStorage 会话查询

范围：

- 增加会话摘要结构。
- 支持加载所有会话摘要。
- 支持按 ID 加载指定会话。
- 支持删除指定会话。

验证：

- 增加存储层测试。

### V2-TASK-004 完善会话列表 UI

范围：

- 左侧列表展示数据库中的所有会话。
- 点击会话切换当前会话。
- 新建和删除会话更新列表。

验证：

- 多会话切换后内容正确。

### V2-TASK-005 增加停止生成

范围：

- 发送中按钮切换为停止。
- 调用 `AIClient::cancel()`。
- 停止后保存当前已生成内容。

验证：

- 生成中可停止。
- 停止后可以继续发送下一条消息。

### V2-TASK-006 增加复制消息

范围：

- `MessageWidget` 增加复制按钮。
- 复制原始文本到剪贴板。

验证：

- 用户消息和 AI 消息均可复制。

### V2-TASK-007 支持基础 Markdown 渲染

范围：

- 评估使用 Qt 内置 rich text / Markdown 能力。
- 先支持标题、列表、代码块的基础展示。

验证：

- Markdown 回复显示可读。
- 流式更新仍稳定。

### V2-TASK-008 增加基础日志

范围：

- 增加日志初始化。
- 写入应用数据目录下的日志文件。
- 不记录 API Key。

验证：

- 网络失败时能在日志中看到原因。

### V2-TASK-009 角色提示词模板

范围：

- 增加简单模板列表。
- 支持保存、选择和应用模板到当前会话。

验证：

- 选择模板后，请求体中的 `system` 消息更新。

### V2-TASK-010 V2 验收与复盘

范围：

- 编写 V2 验收记录。
- 更新 README。
- 更新打包说明。
- 总结 V2 技术债和 V3 方向。

验证：

- 构建、测试、手工验收全部通过。

## 5. 推荐执行顺序

```text
V2-TASK-001 -> V2-TASK-002
V2-TASK-003 -> V2-TASK-004
V2-TASK-005 -> V2-TASK-006
V2-TASK-007 -> V2-TASK-008
V2-TASK-009 -> V2-TASK-010
```

优先先做架构整理，再堆功能。否则多会话、停止生成和模板功能会继续压到 `MainWindow`，后续维护成本会明显变高。

## 6. V2 风险点

- `ApplicationController` 重构可能引入行为回归。
- 多会话切换涉及 UI 状态、数据库状态和生成中状态，需要明确边界。
- 停止生成需要处理 `QNetworkReply` 生命周期，避免重复释放或悬空回调。
- Markdown 渲染如果做得过早、过复杂，可能影响流式输出稳定性。
- 日志不能泄露 API Key。

## 7. V2 验收标准

V2 完成时应满足：

- 自动化测试全部通过。
- 主窗口职责明显减少。
- 可以创建、切换、删除多个会话。
- 可以停止正在生成的回复。
- 可以复制消息。
- AI 回复支持基础 Markdown 展示。
- 常见错误有清楚提示和日志记录。
- README 和打包说明同步更新。
