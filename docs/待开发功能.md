## 3. 长期方向

| 功能 | 状态 | 进入条件 | 说明 |
|------|:---:|----------|------|
| 角色扮演系统 | ⬚ | 主线开发助手体验稳定后 | Persona、Emotion、Narration 可作为长期玩法，但不应干扰编程助手主定位 |
| 双 Agent 互审 | ⬚ | 插件系统、审查结构化、成本控制稳定后 | 适合高价值审查和自更新提案验证，不适合立即引入主循环 |
| 游戏观察与半自动策略 | ⬚ | 游戏助手 UI、数据集、YOLO 推理先跑通 | 默认观察模式，不让 Agent 一开始直接执行动作 |
| 受控自动模式 | ⬚ | 停止热键、前台窗口校验、动作日志和授权项目机制完成后 | 仅面向单机、自研、测试环境或授权场景 |
| 逆向学习助手 | ⬚ | 安全边界、合法用途确认和只读资料整理先完成 | 定位为学习笔记/报告工具，不做注入和内存修改 |
| 完整跨平台适配 | ⬚ | PlatformServices 真实集成后 | 先保证 Windows 主线稳定，再评估 macOS/Linux |

## 4. 跳过项

| 功能 | 状态 | 原因 | 后续处理 |
|------|:---:|------|----------|
| Catch2 测试框架迁移 | ⏭ 跳过 | 当前自定义 assert 测试已覆盖主线，迁移成本高、收益低，容易制造无业务价值的大范围改动 | 保留学习文档；只有测试规模继续显著增长或断言表达力成为瓶颈时再评估 |
| 后台静默自更新并替换 exe | ⏭ 跳过 | 桌面程序自替换涉及权限、杀进程、回滚和安全风险；v1.0 只做手动检查/下载方向 | 后续最多做手动下载和用户确认安装，不做静默覆盖 |
| Python 接管 Agent 主循环 | ⏭ 跳过 | 项目架构明确 C++ 是主控层，Python sidecar 只做能力层；第二套主循环会导致状态和调试复杂度上升 | Python 继续承载模型、Web、浏览器、文档、视觉等能力 |

## 5. 弃用或明确不做

| 功能 | 状态 | 弃用原因 | 替代方案 |
|------|:---:|----------|----------|
| 在线游戏自动化 | 🚫 不做 | 法律、账号、平台规则和项目声誉风险高，超出编程助手定位 | 游戏助手仅面向单机、自研、测试环境或明确授权场景 |
| 反作弊绕过 | 🚫 不做 | 涉及规避安全机制，不符合项目边界 | 只保留合法安全学习和风险说明 |
| DLL 注入 / 驱动 / 进程隐藏 | 🚫 不做 | 容易变成外挂或攻击工具，风险不可控 | 逆向学习助手只做笔记、概念解释和只读资料整理 |
| 写内存 / 改数值 / 自动扫描作弊地址 | 🚫 不做 | 直接指向作弊能力，与项目安全边界冲突 | 可记录用户自有教学样例的学习笔记，但不提供执行能力 |
| 封包篡改 / 重放 / 绕过验证码或风控 | 🚫 不做 | 可能造成滥用和违规 | 不提供替代执行能力，只允许高层安全边界说明 |
| Agent 直接启动游戏自动动作 | 🚫 不做 | 自动化动作需要 UI 安全上下文、用户确认、前台窗口校验和停止机制 | 先开放观察、数据检查、策略审查；动作执行必须由 GameAssistantDialog 控制 |

## 6. 从待开发转为已实现的规则

完成一个功能后：

1. 在本文件中将对应项移除或改为“已完成并迁移”说明。
2. 在 `docs/已实现功能.md` 添加能力说明和当前测试状态。
3. 更新 `docs/DEVELOPMENT_PLAN.md` 的状态、日期和来源。
4. 更新 `docs/DOCUMENT_INDEX.md` 的文档状态。
5. 如果涉及源码结构或调用关系，刷新 codebase-memory-mcp 索引并更新调用关系文档。
