# V8+ Agent 详细开发路线

本文档基于当前开发进度、[Agent 与电脑交互后续规划](22-agent-automation-roadmap.md)、[V8 Roadmap](26-v8-agent-workspace-roadmap.md)、[下一版本开发计划](27-next-version-development-plan.md)，并参考 `优化方向.md`。`UI优化方向.md` 暂不纳入版本开发计划。V9 及以后执行级拆分见 [V9+ 后续开发规划](31-v9-plus-development-roadmap.md)。

当前版本状态：

- V6：受控文件工具已完成。
- V7：Agent 计划、工具目录、计划解析、计划预览和低风险文本工具执行已完成第一版。
- V8.1：工作目录文件 Agent MVP 已完成第一版，见 [V8.1 验收记录](29-v8-acceptance-notes.md)。
- V8.2/V8.3：Agentic Loop、工具注册表与 Function Calling 兼容层已完成第一版，见 [V8.2/V8.3 验收记录](30-v8-2-v8-3-acceptance-notes.md)。
- V9：受控命令执行 MVP 第一版已完成，见 [V9 验收记录](33-v9-command-execution-acceptance-notes.md)。
- V9.1：构建测试技能和项目目录配置化已完成第一版，见 [V9.1 验收记录](34-v9-1-command-skills-acceptance-notes.md)。
- V9.2：原生 Function Calling 接入已完成第一版，见 [V9.2 验收记录](35-v9-2-function-calling-acceptance-notes.md)。
- V10.1：项目级指令文件已完成第一版，见 [V10.1 验收记录](36-v10-project-instructions-acceptance-notes.md)。
- V10.2：外部技能文件系统已完成第一版，见 [V10.2 验收记录](37-v10-2-external-skills-acceptance-notes.md)。
- V10.3：受控工作记忆已完成第一版，见 [V10.3 验收记录](38-v10-3-project-memory-acceptance-notes.md)。
- 当前适合推进：V11 工具生态和开发者工作流扩展。
- V9 及以后详细任务：见 [V9+ 后续开发规划](31-v9-plus-development-roadmap.md)。

当前不适合直接推进：

- 键盘鼠标模拟。
- 浏览器自动化。
- 长期记忆系统。
- 大规模 UI 改造。
- 游戏逆向、DLL 注入、内存修改等高风险方向。

原因：命令执行底层已经具备第一版，但还需要技能封装、项目目录配置和真实 AI 验证，之后再扩展记忆、工具生态和电脑感知。

## 2. 总体路线

推荐版本关系：

```text
V8.1：工作目录文件 Agent MVP
-> V8.2：Agentic Loop 与运行时安全
-> V8.3：工具注册表与 Function Calling 兼容层
-> V9：受控命令执行 MVP
-> V9.1：构建测试技能和项目目录配置化
-> V9.2：原生 Function Calling 接入
-> V10：项目级指令文件、技能系统与工作记忆
-> V11：工具生态扩展与开发者工作流
-> V12：电脑感知、操作记录和确认回放
-> V13：受控设备输入模拟
-> V14：个人 AI 管家能力整合
```

其中 V8.1 到 V9 是当前最有工程价值、最适合简历表达、也最容易验证的阶段。

## 3. 设计原则

### 3.1 本地能力分级

| 等级 | 能力 | 版本 |
| --- | --- | --- |
| L1 | 文本处理、JSON/Markdown 工具 | 已完成 |
| L2 | 用户选择路径的文件工具 | 已完成 |
| L3 | 默认工作目录内自动文件操作 | V8.1 |
| L4 | Agentic Loop 连续观察和重规划 | V8.2 |
| L5 | 白名单命令执行 | V9 |
| L6 | 开发者命令技能和项目目录配置 | V9.1 |
| L7 | 项目级指令、外部技能系统、工作记忆 | V10 |
| L8 | 搜索、浏览器、数据处理、发布打包 | V11 |
| L9 | 屏幕感知、OCR、窗口检测、设备输入 | V12+ |

### 3.2 安全原则

- AI 只建议，最终执行必须经过本地工具目录和策略校验。
- 文件内容、工具输出、网页内容和屏幕内容都视为不可信数据。
- 工作目录外不自动读写。
- `.git`、密钥、凭据、证书等受保护文件禁止自动删除或覆盖。
- 命令执行必须使用白名单和参数模板，不能直接执行任意 PowerShell 字符串。
- 设备输入模拟必须有前台窗口校验、停止按钮和审计日志。
- 日志记录操作摘要，不记录 API Key、Token、密码、完整文件正文或敏感路径。

## 4. V8.1：工作目录文件 Agent MVP

目标：

- 让应用可以在默认 Agent 工作目录内自动生成和管理文件。

核心任务：

- 新增 `WorkspaceFileService`。
- 实现 `workspace.write_text`、`workspace.read_text`、`workspace.list_directory`。
- 后续补 `workspace.overwrite_text`、`workspace.delete_file`。
- 接入 `AgentToolCatalog`。
- 接入 `AgentPlanExecutor`。
- 增加文件参数校验。
- 增加提示词注入防护测试。
- 增加 V8.1 验收记录。

验收标准：

- 未指定路径时文件默认保存到 Agent 工作目录。
- 相对路径只能解析到工作目录内。
- 工作目录外绝对路径被拒绝。
- 普通文件可写入、读取、覆盖和删除。
- 受保护文件不可删除或覆盖。
- 文件内容中的指令不能绕过本地策略。
- `ctest` 全部通过。

当前最优先任务：

```text
TASK-001 工作目录文件服务
```

## 5. V8.2：Agentic Loop 与运行时安全

目标：

- 从“一次生成完整计划”升级为“观察 -> 思考 -> 行动 -> 再观察”的循环执行模式。

当前 V7 模式：

```text
用户目标 -> AI 生成完整计划 -> 本地解析 -> 用户逐步执行 -> 结束
```

目标 V8.2 模式：

```text
用户目标
-> Observe：读取当前状态和上一步结果
-> Think：AI 判断下一步
-> Act：执行一个工具步骤
-> Evaluate：判断完成、继续、失败或停止
-> 回到 Observe
```

核心任务：

- 新增 `AgentLoopController` 或等价模块。
- 每轮只请求一个下一步动作，而不是整批计划。
- 增加 `done=true` 终止信号。
- 增加最大步数，例如 5 步。
- 增加单步超时，例如 30 秒。
- 工具失败后允许 AI 重规划。
- 增加循环检测，避免重复执行同一步。
- 增加 Agent 专用审计日志。

验收标准：

- Agent 能基于文件工具结果继续下一步。
- 工具失败后能暂停或重新规划。
- 达到步数上限后停止。
- 用户点击停止后不再执行后续步骤。
- 日志能看到工具调用链和结果摘要。

## 6. V8.3：工具注册表与 Function Calling 兼容层

目标：

- 减少 `AgentPlanExecutor` 中的硬编码分支，为后续工具扩展和 Function Calling 做准备。

核心任务：

- 新增 `AgentTool` 抽象接口。
- 新增 `ToolRegistry`。
- 每个工具提供：
  - `toolId`
  - 描述信息
  - 参数 schema
  - 风险等级
  - `execute(params)`
- `AgentToolCatalog` 从注册表生成。
- `AgentPlanExecutor` 通过注册表执行工具。
- 预留 Function Calling 请求体生成能力。
- 保留 JSON plan fallback，避免 DeepSeek 或其他兼容接口行为不稳定时阻塞。

Function Calling 策略：

- 优先做兼容层，不立即替换全部 JSON 解析。
- 如果模型支持 tool/function calling，则使用原生工具调用。
- 如果模型不支持，则继续使用现有 JSON plan parser。

验收标准：

- 文本工具和工作目录工具都能通过注册表执行。
- 工具 ID 唯一。
- Prompt 和工具目录由同一份注册表生成，避免描述不一致。
- JSON plan fallback 仍然可用。

## 7. V9：受控命令执行与构建测试技能

目标：

- 让 Agent 可以执行有限、可审计、可停止的白名单命令。

允许能力：

- `git status`
- `git diff --check`
- `ctest --test-dir build-qt --output-on-failure`
- `cmake --build build-qt`
- `dir` / `Get-ChildItem` 的固定模板。

禁止能力：

- 任意 PowerShell/CMD 字符串。
- 删除、格式化、注册表修改、服务修改。
- 静默安装软件。
- 读取或打印 API Key、Token、密码。
- 后台无人值守长期命令。

核心任务：

- 新增 `CommandPolicy`。
- 新增 `CommandRunner`。
- 命令白名单和参数模板。
- 工作目录限制。
- 超时控制。
- stdout/stderr 摘要。
- 命令结果回传时标记为不可信数据。
- 新增命令执行测试。

验收标准：

- 白名单命令可以执行。
- 非白名单命令失败。
- 超时命令被终止。
- 命令输出不会完整写入日志。
- Agent 不能拼接任意 shell。

## 8. V10：项目级指令、外部技能系统与工作记忆

目标：

- 让 Agent 从“工具调用器”升级为“能记住项目约定、复用流程的项目助手”。
- 该方向已从原 V9.1 后移到 V10；V9.1 当前实际用于开发者命令技能和项目目录配置化。

### 9.1 项目级指令文件

建议文件：

```text
AGENT.md
```

内容：

- 项目技术栈。
- 构建和测试命令。
- 禁止修改的目录。
- Git 工作流约定。
- 用户偏好。

不建议命名为 `CODEX.md`，避免和当前工具或目录名混淆。

### 9.2 技能系统

新增模块：

```text
src/skills/
```

技能示例：

- `build-debug.skill.md`
- `fix-compile-errors.skill.md`
- `run-tests.skill.md`
- `prepare-release.skill.md`

技能结构：

- 名称。
- 描述。
- 适用场景。
- 需要的工具。
- 风险等级。
- 步骤模板。

### 9.3 工作记忆

新增模块：

```text
src/memory/
```

记录内容：

- 用户明确要求记住的偏好。
- 项目级决策。
- 常用目录。
- 已验证的构建/测试流程。

验收标准：

- Agent 能读取项目指令。
- Agent 能列出可用技能。
- 用户明确保存的记忆可跨会话读取。
- 记忆写入需要来源标记，不自动保存敏感内容。

## 9. V11：工具生态扩展与开发者工作流

目标：

- 在文件 Agent 和命令执行稳定后，扩展更完整的开发者工具链。

推荐工具：

| 工具 | 能力 | 说明 |
| --- | --- | --- |
| `web.search` | 搜索公开资料 | 需要结果摘要和来源链接 |
| `git.review_diff` | 分析 git diff | 只读工具 |
| `data.csv_read` | 读取 CSV | 工作目录内 |
| `data.csv_write` | 写 CSV | 工作目录内 |
| `release.package` | 打包 release | 基于白名单命令 |
| `logs.summarize` | 总结日志 | 不输出敏感正文 |

暂缓工具：

- 浏览器点击填表。
- 自动登录。
- 跨应用操作。

验收标准：

- 每个工具都有工具目录描述、参数 schema、风险等级和测试。
- 工具结果都按不可信数据处理。
- 工具失败后 Agent 能给出降级方案。

## 10. 后续：对话能力和数据能力增强

目标：

- 改善非 UI 大改前提下的核心对话能力。

可选任务：

- 消息编辑和重新生成。
- 对话分叉。
- 引用回复。
- 会话全文搜索升级到 SQLite FTS。
- 会话标签。
- 使用统计。

说明：

- 这部分不是 UI 大改，而是数据和交互能力增强。
- 视觉层面的 UI 优化继续独立规划，不进入 V8/V9 主线。

验收标准：

- 编辑消息后上下文正确重建。
- 分叉会话不会污染原会话。
- FTS 搜索比 LIKE 查询更稳定。

## 11. V12/V13：电脑感知与受控设备输入

目标：

- 让 Agent 能感知屏幕和窗口，并在明确授权下模拟有限输入。

推荐分层：

- `ScreenCapture`：截图。
- `WindowDetector`：窗口枚举和前台窗口确认。
- `OcrService`：OCR，优先 Windows OCR API。
- `UiAutomationService`：Windows UI Automation 控件定位。
- `InputSimulator`：SendInput 封装。

安全边界：

- 不自动输入密码、API Key、验证码。
- 不绕过 UAC 或系统权限提示。
- 不在后台偷偷操作。
- 执行前展示目标窗口和操作步骤。
- 必须有停止按钮。
- 不记录屏幕敏感内容。

验收标准：

- 可以枚举窗口。
- 可以截图并保存到工作目录。
- 可以在测试窗口中定位控件。
- 可以在测试窗口中输入文本。
- 不对真实游戏、浏览器登录态或敏感窗口做自动化。

## 12. V14：个人 AI 管家能力整合

目标：

- 在文件、命令、记忆、技能、感知和输入都稳定后，组合成更完整的个人助手。

候选场景：

- 文件整理。
- 工作日报。
- 项目检查。
- 本地资料摘要。
- 角色扮演长期记忆。
- 简单定时提醒。

暂不进入正式路线：

- 游戏逆向。
- DLL 注入。
- 内存修改。
- 绕过反作弊。

这些方向风险高、验证成本高，不适合作为当前简历项目主线。

## 15. 简历表达分阶段

V8.1 完成后：

> 实现受控文件 Agent，支持 AI 基于结构化计划在默认工作目录内创建、读取和修改文件，并通过工作目录策略、受保护文件拦截和提示词注入防护限制误操作。

V8.2/V8.3 完成后：

> 将 Agent 从一次性计划执行升级为观察、决策、行动、再观察的循环模式，并引入工具注册表和 Function Calling 兼容层，提升工具扩展性和模型输出稳定性。

V9 完成后：

> 在本地桌面 AI 应用中实现白名单命令执行能力，支持构建、测试和 Git 状态检查，并通过命令模板、超时控制、输出摘要和审计日志降低系统操作风险。

V9.1 完成后：

> 将常见开发流程整理为开发者命令技能，例如检查改动、提交前检查、构建并测试和定位测试失败。技能会展开为受控 `command.*` 工具步骤，仍经过白名单命令策略、用户确认和测试验证。

V10 以后：

> 设计项目级指令、技能系统和跨会话工作记忆，使 Agent 能复用项目流程和用户偏好，形成可持续演进的本地开发助手。
