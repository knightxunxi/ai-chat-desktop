# V7 Roadmap

本文档用于规划 AI Chat Desktop 的 V7 阶段。V7 的核心目标是让 AI 从“普通聊天回复”升级为“可以分析目标、拆解任务、建议工具调用”的受控 Agent 雏形。

执行状态：V7 规划完成。当前 `codex/v7-agent-planning` 开发分支已完成 V7-TASK-001 至 V7-TASK-008 的第一版；真实 AI 计划生成仍需合并前手工验证。

前置说明：当前 `main` 仍以 V5 为稳定版本。V7 的执行依赖 V6 受控本地文件工具能力；如果 V6 尚未合并到 `main`，V7 应先完成设计、计划解析器和 UI 预览，不直接进入工具执行。

## 1. V7 目标

V7 重点解决四类问题：

- 任务拆解：AI 根据用户目标生成分步骤计划。
- 工具建议：AI 只能建议调用已有工具，不能绕过本地校验直接执行。
- 用户确认：每一步工具调用前都需要用户确认。
- 结果回传：工具执行结果展示给用户，用户确认后才允许回传给 AI。

V7 的定位是“受控半自动 Agent”，不是“AI 自动控制电脑”。

## 2. 技术类型

| 技术类型 | 用途 | 预期落点 |
| --- | --- | --- |
| 结构化输出 | 让 AI 返回可解析的计划 | JSON plan schema |
| C++ 数据模型 | 保存计划、步骤、状态和工具参数 | `src/core` 或 `src/app` |
| 工具目录 | 描述可用工具、输入限制和风险等级 | `src/tools` |
| 计划解析器 | 校验 AI 返回的计划结构 | Agent plan parser |
| Qt Dialog / Panel | 展示计划并等待用户确认 | Plan review UI |
| AppLogger | 记录计划生成、确认、执行和失败 | Agent 日志 |
| CTest | 验证计划解析和状态流转 | parser / workflow tests |
| 安全策略 | 防止未确认执行和越权工具调用 | V7 agent safety rules |

## 3. V7 范围

### 3.1 必做范围

- 新增 V7 Agent 安全设计。
- 定义可用工具目录，至少覆盖 V5 文本工具；如果 V6 已合并，再覆盖 V6 文件工具。
- 定义 AI 计划 JSON 结构。
- 实现计划解析和本地校验。
- 新增计划预览/确认界面。
- 支持用户确认后执行单个低风险工具步骤。
- 支持用户取消、跳过和停止计划。
- Agent 操作写入日志。
- 增加计划解析、工具目录和状态流转测试。
- 更新 README、学习资料和验收记录。

### 3.2 建议范围

- 限制最大计划步数，例如 5 步。
- 给每一步显示风险等级和原因。
- 工具参数展示为只读文本，避免隐藏执行内容。
- 工具失败后允许用户选择停止或让 AI 重新规划。
- 工具结果回传 AI 前让用户确认。
- 增加 UI smoke test 覆盖计划窗口基础生命周期。

### 3.3 V7 暂不包含

- Shell / PowerShell / CMD 命令执行。
- 任意脚本运行。
- 自动键盘、鼠标或设备输入。
- 后台无人值守执行。
- 自动读取未由用户选择的路径。
- 自动发送文件内容给 AI。
- 自动覆盖、删除或移动文件。
- 插件市场。
- 云端 Agent。

## 4. 推荐里程碑

### M1 Agent 安全设计和工具目录

目标：

- 明确 AI 可以建议什么，不能建议什么。
- 明确每个工具的输入、输出、风险等级和确认要求。

任务：

- 新增 V7 Agent 安全设计文档。
- 定义工具目录结构。
- 给现有工具补充机器可读元数据。
- 明确 V7 不支持命令执行和设备输入。

验收标准：

- 文档能说明工具建议、用户确认、日志和失败处理边界。
- 所有进入 V7 的工具都有 ID、名称、说明、输入限制和风险等级。

### M2 计划数据模型和解析器

目标：

- 把 AI 输出从自然语言变成可校验的结构化计划。

建议计划结构：

```json
{
  "summary": "计划摘要",
  "steps": [
    {
      "id": "step-1",
      "title": "步骤标题",
      "toolId": "json.format",
      "reason": "为什么需要这一步",
      "risk": "low",
      "parameters": {}
    }
  ]
}
```

任务：

- 定义计划、步骤、状态的数据结构。
- 实现 JSON 解析和字段校验。
- 校验工具 ID 必须存在于工具目录。
- 校验步骤数量上限。
- 非法计划返回明确错误。

验收标准：

- 合法计划可以解析。
- 缺字段、未知工具、步骤过多、非法风险等级都会失败。
- 计划解析器可独立测试。

### M3 AI 计划生成入口

目标：

- 让用户可以选择“生成计划”，由 AI 返回结构化任务拆解。

任务：

- 设计 Agent planning prompt。
- 将可用工具目录压缩成 AI 可理解的工具说明。
- 请求 AI 返回 JSON 计划。
- 对返回结果做解析和错误提示。
- 失败时允许用户回到普通聊天。

验收标准：

- AI 能根据用户目标生成计划。
- 计划生成失败不会影响普通聊天。
- AI 返回的计划必须通过本地校验才能展示。

### M4 计划预览和确认 UI

目标：

- 用户能清楚看到每一步将要做什么，并决定是否执行。

任务：

- 新增计划预览窗口或侧栏。
- 展示计划摘要、步骤标题、工具、原因、风险等级和参数。
- 每一步提供执行、跳过、取消。
- 整个计划提供停止。
- 执行前再次确认有文件读取或输出回传风险的步骤。

验收标准：

- 用户不需要读日志也能知道即将执行什么。
- 工具步骤不会在未确认时执行。
- UI 支持取消和停止。

### M5 单步工具执行和结果展示

目标：

- 用户确认后执行工具，并把结果作为下一步分析材料。

任务：

- 将计划步骤映射到现有工具。
- 执行成功后展示结果摘要。
- 执行失败后展示错误并暂停计划。
- 用户确认后才允许把工具结果回传给 AI。
- AI 根据结果给出后续建议或最终总结。

验收标准：

- 工具执行与普通聊天流程解耦。
- 工具结果不会自动发送给 AI。
- 日志记录计划 ID、步骤 ID、工具 ID 和执行结果摘要。

### M6 测试、验收和学习资料

目标：

- 让 V7 不只靠手工演示，而是有可验证的安全边界和流程。

任务：

- 增加计划解析器测试。
- 增加工具目录测试。
- 增加 Agent 状态流转测试。
- 可选增加计划 UI smoke test。
- 输出 V7 验收记录。
- 更新 README 和 `learn/`。

验收标准：

- 本地构建通过。
- CTest 全部通过。
- 文档和实际能力一致。

## 5. V7 任务拆分

### V7-TASK-001 Agent 安全设计

范围：

- 新增 V7 安全设计文档。
- 明确 AI 只能建议，不能绕过用户确认执行。
- 明确文件内容、工具结果和日志的敏感信息处理规则。

验证：

- 文档说明 V7 不包含命令执行和设备输入模拟。

当前状态：已完成第一版，见 [V7 Agent 安全设计](23-v7-agent-safety-design.md)。

### V7-TASK-002 工具目录设计

范围：

- 定义工具目录数据结构。
- 为 V5/V6 工具建立工具 ID、说明、输入限制和风险等级。
- 明确哪些工具可以进入 Agent 建议范围。

验证：

- 工具目录测试覆盖工具 ID 唯一性和风险等级。

当前状态：已完成第一版，覆盖 V5 文本工具和 V6 文件工具。

### V7-TASK-003 计划模型和解析器

范围：

- 定义计划和步骤模型。
- 实现 JSON plan parser。
- 校验步骤数量、工具 ID、必填字段和风险等级。

验证：

- 单元测试覆盖合法和非法计划。

当前状态：已完成第一版，支持 JSON 计划解析、工具 ID 校验、步骤数量限制、字段校验和风险等级提升。

### V7-TASK-004 AI 计划生成

范围：

- 新增生成计划入口。
- 调用现有 AI 客户端请求结构化计划。
- 解析 AI 返回结果。
- 失败时展示可理解错误。

验证：

- 使用真实 AI Key 手工验证至少 3 个目标可以生成计划。
- 非 JSON 回复不会导致程序崩溃。

当前状态：已完成计划 Prompt 生成器和真实 AI 计划请求入口。请求完成后会解析 JSON 计划，解析失败时只提示错误，不影响普通聊天。

### V7-TASK-005 计划预览 UI

范围：

- 新增计划预览窗口或主窗口侧栏。
- 展示步骤、工具、参数、风险和确认按钮。
- 支持跳过、取消、停止。

验证：

- UI smoke test 或手工验收覆盖窗口打开、关闭和按钮状态。

当前状态：已完成第一版计划预览窗口，支持查看步骤、风险、参数和输出。

### V7-TASK-006 单步工具执行

范围：

- 用户确认后执行单个工具步骤。
- 展示输出和错误。
- 执行失败后暂停计划。

验证：

- 本地工具至少覆盖一个执行路径。
- 如果 V6 已合并，文件工具至少覆盖一个执行路径。
- 未确认时不会执行工具。

当前状态：已完成低风险文本工具的单步执行。文件工具步骤不从计划参数直接执行，仍要求使用 V6 文件工具窗口完成路径选择。

### V7-TASK-007 结果回传和继续规划

范围：

- 工具结果可由用户确认后回传 AI。
- AI 根据结果给出下一步或最终总结。
- 限制最大继续轮数，避免无限循环。

验证：

- 手工验证工具结果不会自动发送。
- 超过轮数限制时停止并提示。

当前状态：已完成输出插入聊天输入框和用户确认后的继续规划基础能力，工具结果不会自动发送给 AI，继续规划有轮次上限。

### V7-TASK-008 V7 验收和项目展示更新

范围：

- 新增 V7 验收记录。
- 更新 README。
- 更新 `learn/` 架构、技术栈和面试问答。
- 更新简历表达建议。

验证：

- 文档链接完整。
- 简历描述不夸大为“全自动 Agent”。

当前状态：已完成第一版，见 [V7 验收记录](24-v7-acceptance-notes.md)。

## 6. 推荐执行顺序

```text
V7-TASK-001
-> V7-TASK-002
-> V7-TASK-003
-> V7-TASK-004
-> V7-TASK-005
-> V7-TASK-006
-> V7-TASK-007
-> V7-TASK-008
```

优先做安全设计、工具目录和计划解析器。没有这三项，AI 计划生成会变成不可控自然语言流程，后续 UI 和执行都缺少边界。

## 7. 风险点

- AI 可能生成不存在的工具 ID，需要本地校验。
- AI 可能把自然语言混进 JSON，需要解析失败提示。
- 文件内容可能包含提示注入，不应直接让文件内容控制工具执行。
- 工具结果可能包含敏感信息，回传 AI 前需要用户确认。
- 多步计划可能无限循环，需要设置最大步数和最大继续轮数。
- UI 如果隐藏参数，用户无法判断执行风险。
- 日志不能记录文件正文、聊天正文、API Key 或完整目录。

## 8. V7 验收标准

V7 完成时应满足：

- Agent 安全设计完成。
- 工具目录完成，并覆盖当前可用的低风险工具。
- AI 可以生成结构化任务计划。
- 本地可以解析和校验计划。
- 用户可以预览计划步骤。
- 工具执行前必须用户确认。
- 用户可以跳过、取消或停止计划。
- 工具结果不会自动回传 AI。
- 执行日志可追踪，且不记录敏感正文。
- 新增测试通过。
- README、学习资料和验收记录同步更新。

## 9. V8 衔接

V7 完成后，V8 先考虑默认工作目录和自动文件生成。受控命令执行后移到 V9。

V8 的进入条件：

- V7 的计划解析和用户确认稳定。
- 工具执行日志稳定。
- 用户可以可靠停止 Agent 流程。
- V7 已经证明 AI 不会绕过本地校验直接执行工具。

只有满足这些条件，再加入默认工作目录、工作目录路径策略、自动文件生成和文件内容提示词注入防护。命令白名单、固定工作目录、超时控制和命令输出摘要放到 V9。

## 10. 简历表达方向

V7 完成后可以考虑这样描述：

> 在 C++/Qt 桌面 AI 应用中实现受控 Agent 雏形，支持 AI 基于用户目标生成结构化任务计划，并通过工具目录、计划校验、用户确认和日志审计限制本地工具调用；工具执行结果需用户确认后才回传 AI，避免未授权自动化操作。

这个表达重点是“结构化计划、工具目录、用户确认、安全边界”，不要写成“AI 自动控制电脑”。
