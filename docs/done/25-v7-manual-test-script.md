# V7 手工验证脚本

本文档用于 V7 合并前的真实 API 手工验收。目标是确认 Agent 计划生成、计划解析、用户确认、低风险工具执行和继续规划流程符合安全边界。

执行状态：待手工验证。当前脚本应在 `codex/v7-agent-planning` 分支构建通过后执行。

## 1. 前置条件

- 当前分支为 V7 开发分支。
- `cmake --build build-qt` 已通过。
- `ctest --test-dir build-qt --output-on-failure` 已通过。
- 应用设置中已经保存有效的 DeepSeek 或 OpenAI 兼容 API Key。
- Base URL、模型名称和语言设置符合当前测试目标。
- 测试过程中不要把 API Key、完整聊天正文或敏感文件内容提交到 Git。

推荐启动方式：

```powershell
$env:PATH="D:\QT\6.10.2\mingw_64\bin;D:\QT\Tools\mingw1310_64\bin;$env:PATH"
.\build-qt\AIChatDesktop.exe
```

## 3. 用例 A：低风险 JSON 格式化计划

输入框填入：

```text
请生成一个安全计划，把下面 JSON 格式化并方便我检查：
{"name":"ai-chat","stack":["cpp","qt"],"version":7}
```

操作：

- 点击“Agent 计划”。
- 等待计划窗口打开。
- 检查步骤工具是否为 `json.format` 或同类低风险文本工具。
- 点击“执行步骤”。
- 检查输出是否变成缩进后的 JSON。
- 点击“插入输出”，确认输出进入聊天输入框且没有自动发送。

预期结果：

- 计划窗口可以打开。
- 参数和风险等级可见。
- 未点击“执行步骤”前不会产生工具输出。
- 点击后输出正常显示。
- 输出只插入输入框，不自动发送给 AI。

## 4. 用例 B：Markdown 整理计划

输入框填入：

```text
请生成一个安全计划，整理下面 Markdown 的多余空行和首尾空白：


# 标题


  - 项目一
  - 项目二


```

操作：

- 点击“Agent 计划”。
- 检查是否生成 `markdown.cleanup` 或 `text.cleanup` 步骤。
- 执行低风险步骤。
- 检查输出是否只做空白整理，没有改变核心内容。

预期结果：

- 低风险文本工具可以执行。
- 输出内容可复制、可插入。
- 不需要额外文件权限。

## 5. 用例 C：文件工具安全边界

输入框填入：

```text
请生成一个计划，读取项目 README.md 并总结这个项目的功能。
```

操作：

- 点击“Agent 计划”。
- 检查计划是否可能建议 `file.read_text`。
- 如果出现文件读取步骤，选中该步骤。
- 检查“执行步骤”按钮是否不可用。

预期结果：

- 文件工具步骤显示为中风险。
- 计划窗口不能直接按 AI 参数读取文件。
- 用户仍需通过“文件工具”窗口手动选择文件。
- 日志不记录文件正文。

## 6. 用例 D：真实模型返回 Markdown 代码块

输入框填入：

```text
请生成一个安全计划，把下面文本整理成更紧凑的格式。即使你想用 markdown 代码块包裹 JSON，也必须保证 JSON 内容符合工具计划结构：
    hello      world
```

操作：

- 点击“Agent 计划”。
- 等待返回。

预期结果：

- 如果模型返回纯 JSON，计划正常打开。
- 如果模型返回 `json` 代码块包裹的 JSON，解析器仍能提取并打开计划窗口。
- 如果模型返回不合规内容，只提示解析失败，不影响普通聊天。

## 7. 用例 E：继续规划限制

操作：

- 使用用例 A 或 B 执行一个低风险步骤。
- 确认输出已经显示。
- 点击“继续规划”。
- 等待下一轮计划窗口打开。
- 再执行一次低风险步骤并继续规划。
- 达到上限后检查“继续规划”按钮状态。

预期结果：

- 工具输出不会自动发送给 AI。
- 只有点击“继续规划”后，才会把用户已查看的输出作为下一轮计划输入。
- 继续规划达到上限后按钮不可用或提示已达到上限。

## 8. 用例 F：普通聊天不受影响

操作：

- 完成一次 Agent 计划成功或失败测试后，回到主窗口。
- 输入普通问题并点击“发送”。
- 再测试一次“停止”。

预期结果：

- 普通聊天仍能正常发送。
- Agent 计划解析失败不会污染当前会话消息。
- “停止”可以取消当前请求，窗口关闭后不会遗留占用进程。

## 9. 合并前通过标准

V7 合并前至少满足：

- 用例 A、B、C、F 通过。
- 用例 D 至少覆盖纯 JSON 或 Markdown 代码块 JSON 的一种成功路径，并记录模型实际行为。
- 用例 E 验证继续规划不会无限循环。
- 日志中可以看到 Agent 计划请求开始、解析成功或解析失败记录。
- 未发现未确认执行、自动发送工具输出、直接读取 AI 指定路径、程序崩溃或窗口关闭后进程残留。

如果真实模型连续返回不合规 JSON，应优先调整计划 Prompt 或解析提示，不直接放宽本地校验规则。
