# V1 复盘与 V2 规划

本文档对应 V1 阶段 8 的 TASK-020。

## 1. V1 已完成能力

- C++ / Qt 6 / CMake 项目骨架。
- 主窗口、聊天消息视图、设置窗口和基础样式。
- 应用配置模型和本地 `QSettings` 保存。
- 聊天会话、消息、角色提示词核心模型。
- SQLite 聊天记录保存、读取和清空。
- OpenAI 兼容流式 API 客户端。
- SSE 流式响应解析。
- 当前会话角色提示词作为 `system` 消息发送。
- 发送按钮、生成状态、配置缺失提示和基础错误展示。
- 新建会话入口、基础多会话列表、会话切换和最近会话恢复。
- 基础自动化测试。
- Release 构建和 `windeployqt` 发布目录生成。

## 2. 实现偏差

技术方案中建议添加 `ApplicationController`，当前 V1 为了保持实现简单，暂由 `MainWindow` 直接串联配置、存储和 API 客户端。

这个选择让 V1 更快闭环，但也带来一个明显技术债：主窗口类承担了部分流程控制职责。V2 如果继续增加多会话、停止生成、模板和更多错误状态，应优先抽出控制层。

## 3. 技术债

- `MainWindow` 业务流程偏多，需要在 V2 拆出 `ApplicationController`。
- 会话列表支持基础切换，但还不支持重命名、删除和搜索。
- API Key 未加密保存。
- 错误展示仍偏简单，没有日志或详细诊断信息。
- UI 文案通过轻量 `text()` 方法管理，后续应考虑更系统的国际化。
- 缺少真正的端到端 UI 自动化测试。

## 4. 已知问题

- 尚未用真实 API Key 完成最终端到端验收。
- 发布目录已生成，但本轮未完成 GUI 启动人工确认。
- 当前没有停止生成按钮，只能等待请求完成或失败。
- 当前没有 Markdown 渲染，AI 回复以纯文本显示。
- 当前会话列表还缺少重命名、删除和搜索等完整管理能力。

## 5. V2 优先级建议

优先级 P0：

- 抽出 `ApplicationController`，降低 `MainWindow` 复杂度。
- 完善多会话重命名、删除和搜索。
- 增加停止生成。
- 增加更可靠的错误状态和日志。

优先级 P1：

- Markdown 渲染。
- 复制消息内容。
- 角色提示词模板。
- 导出聊天记录。

优先级 P2：

- 多服务商预设。
- 温度、最大 token 等高级参数。
- API Key 更安全的本地存储。
- 更完整的 UI 自动化测试。

## 6. 下一步建议

1. 用有效 API Key 做 `docs/04-v1-acceptance-notes.md` 中的最终手工验收。
2. 按 `docs/05-windows-packaging.md` 生成 Release 发布目录。
3. 提交 V1 收尾改动。
4. 按 `docs/07-v2-roadmap.md` 开始 V2，优先抽出控制层，避免后续功能继续压到 `MainWindow`。
