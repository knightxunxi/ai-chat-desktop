## 4. V11：工具生态扩展与开发者工作流

### 4.1 版本定位

一句话范围：

> 在文件、命令、技能和记忆都稳定后，扩展更多有实际开发价值的工具，并增强已有工具的实用性。

核心目标：

- 新增 5-8 个开发相关工具（Git、日志、数据、搜索等）。
- 每个工具完整进入 `AgentToolRegistry`。
- 每个工具有参数 schema、风险等级、日志策略和测试。
- 工具结果按不可信数据处理，不影响本地安全策略。
- Chat/Agent 统一模式下，工具调用能正常触发计划窗口。

### 4.2 候选工具分级

#### P0（优先实现）

| 工具 ID | 能力 | 技术路线 | 说明 |
|---------|------|----------|------|
| `git.review_diff` | 分析 git diff | `QProcess` + `git diff` 白名单 | 只读，不修改仓库；风险 low |
| `git.review_log` | 分析最近提交记录 | `QProcess` + `git log --oneline -n` | 只读，风险 low |
| `logs.summarize` | 总结日志最近 N 行/关键词匹配 | 直接读日志文件，复用 `workspace.read_text` | 不输出敏感正文；风险 low |

#### P1（第二批）

| 工具 ID | 能力 | 技术路线 | 说明 |
|---------|------|----------|------|
| `data.csv_read` | 读取工作目录内 CSV | 轻量 CSV 解析（无需 Qt SQL） | 限制行数上限（如 5000 行）；风险 low |
| `data.csv_write` | 写工作目录内 CSV | 复用 `workspace.write_text` + 格式校验 | 风险 low-medium（写入操作） |
| `project.find_files` | 按名称/类型搜索项目文件 | 遍历项目目录 + glob 匹配 | 不扫描系统目录；风险 low |

#### P2（第三批，需额外评估）

| 工具 ID | 能力 | 技术路线 | 说明 |
|---------|------|----------|------|
| `web.search` | 搜索公开资料 | HTTP API（需配置搜索接口） | 风险 medium（网络 + 不可信内容注入）；需要来源标记 |
| `release.package` | 按白名单流程打包 | 组合 `command.cmake_build` + 文件复制 | 风险 medium；需要打包目录限制 |

### 4.3 不纳入 V11 的内容

- 浏览器自动化（点击、填表、登录）。
- 键盘鼠标模拟。
- 跨应用操作。
- 长期后台任务。
- UI 大改版。

这些方向在安全策略和用户确认机制成熟后进入 V12/V13。

### 4.4 工具开发规范

每个 V11 工具必须满足：

```text
1. 定义工具 ID（如 git.review_diff）
2. 编写工具描述 + 适用场景（中文/英文双语）
3. 定义参数 schema（类型、必填/可选、默认值）
4. 标记风险等级（low / medium / high）
5. 明确日志策略（记录工具 ID + 参数摘要 + 输出长度，不记录正文）
6. 写出测试用例（正常、空输入、异常、超时）
7. 进入 AgentToolRegistry（AgentToolRegistryFactory）
8. 确认生成 Function Calling schema 正确
```

### 4.5 V11 任务拆分

#### V11-TASK-001：工具规划与设计文档

范围：

- 新建 `docs/40-v11-tool-ecosystem-design.md`，记录每个工具的设计方案。
- 明确 P0/P1/P2 分批策略。
- 定义每个工具的参数 schema、风险等级、日志策略。

验收标准：

- 每个工具都有明确的用途和技术路线描述。
- 不允许、不适合的操作写清楚。

#### V11-TASK-002：`git.review_diff` 与 `git.review_log`

范围：

- 新增 `src/tools/GitReviewTool.h/.cpp`。
- 基于 `QProcess` 调用 `git diff --stat` + `git diff`（受白名单限制）。
- 调用 `git log --oneline -n 20`。
- 输出摘要而非完整 diff（限制 2000 字符以内）。
- 新增 `tests/tools/GitReviewToolTest.cpp`。

验收标准：

- 能读取当前项目的 git diff 统计。
- 能在 diff 为空时正常返回。
- 能在非 git 目录时给出明确错误提示。
- 日志不记录完整 diff 正文。

#### V11-TASK-003：`logs.summarize`

范围：

- 新增 `src/tools/LogSummaryTool.h/.cpp`。
- 读取 `AppLogger` 日志文件（复用 `workspace.read_text`）。
- 按关键词/行数过滤。
- 脱敏处理（屏蔽 API Key、Token 等敏感字段）。
- 新增 `tests/tools/LogSummaryToolTest.cpp`。

验收标准：

- 能按关键词（如 "error"、"warning"）过滤日志。
- 能按最近 N 行返回。
- 不会把完整日志正文写入 Agent 上下文或记忆。

#### V11-TASK-004：`data.csv_read` 与 `data.csv_write`

范围：

- 新增 `src/tools/CsvDataTool.h/.cpp`。
- CSV 读取：轻量解析（逗号分隔 + 引号处理），不依赖 Qt SQL。
- CSV 写入：校验列数一致 + 限制行数（如 500 行）。
- 文件操作限定在工作目录内。
- 新增 `tests/tools/CsvDataToolTest.cpp`。

验收标准：

- 能正确解析标准 CSV。
- 空文件、单列、无 header 等边界情况能处理。
- 写入时列数不一致返回错误。
- 超过行数上限时截断并提示。

#### V11-TASK-005：`project.find_files`

范围：

- 新增 `src/tools/ProjectFindTool.h/.cpp`。
- 遍历项目目录，按后缀名匹配。
- 支持模式匹配（如 `*.cpp`、`*Test*`）。
- 限制返回结果数量（如 100 个）。
- 不扫描 `.git`、`build-*`、`node_modules` 等目录。
- 新增 `tests/tools/ProjectFindToolTest.cpp`。

验收标准：

- 能正确匹配文件模式。
- 排除目录规则生效。
- 结果数量限制生效。

#### V11-TASK-006：工具注册表集成与 Prompt 更新

范围：

- 将 V11 全部新工具加入 `AgentToolRegistryFactory::defaultRegistry()`。
- 更新 `AgentPlanPromptBuilder` 中工具目录生成，确保新工具描述进入 Prompt。
- 更新 `AgentToolCatalog::defaultCatalog()`。

验收标准：

- 所有新工具 ID 唯一。
- 新工具能进入 Agent Prompt 和 Function Calling schema。
- JSON plan fallback 仍然可用。

#### V11-TASK-007：统一模式下的工具调用验证

范围：

- 在 Chat/Agent 模式切换按钮已就位的前提下，验证：
  - Agent 模式下，AI 判断需要工具时能正常返回 plan。
  - plan 解析成功后，聊天消息正确更新（Bug #1 已修复）。
  - plan 解析失败后，回退为普通聊天展示。
  - 取消生成后，占位消息更新为"已停止"（Bug #2 已修复）。
- 建议手工验证脚本覆盖上述四个场景。

验收标准：

- 四个场景均表现正常。
- 不需要增加新的 UI 或架构改动。

#### V11-TASK-008：V11 验收与文档更新

范围：

- 新建 `docs/40-v11-acceptance-notes.md`（或编号顺延）。
- 更新 `README.md` 功能列表、已知限制和文档索引。
- 更新 `learn/01-architecture.md` 和 `learn/05-interview-qa.md`。

验收标准：

- `ctest` 全部通过。
- 功能列表和实际代码能力一致。
- 面试问答覆盖 V11 的新工具能力。

### 4.6 V11 验收标准汇总

- 所有 P0 工具（`git.review_diff`、`git.review_log`、`logs.summarize`）有完整实现和测试。
- 每个工具都在 `AgentToolRegistry` 中注册，有参数 schema 和风险等级。
- 工具结果都标记为不可信数据，不影响本地策略。
- `ctest` 全部通过。
- 统一模式下工具调用能正常弹出计划窗口，不会卡死或消息丢失。

## 5. V12：电脑感知、操作记录和确认回放

> ⚠️ **2026-06-03 更新：** V12-V15 路线已根据深度对标分析重新规划，详见 [44-v12-v15-roadmap.md](44-v12-v15-roadmap.md)。以下内容保留为历史参考。

### 5.1 目标

- 让应用"看见"桌面环境，并记录操作链路，为后续输入模拟做准备。

### 5.2 建议能力

| 能力 | 技术路线 | 优先级 |
|------|----------|--------|
| 窗口枚举 | Windows API `EnumWindows` | P0 |
| 前台窗口检测 | `GetForegroundWindow` + 标题获取 | P0 |
| 截图保存到工作目录 | `BitBlt` / `PrintWindow` | P1 |
| OCR 识别截图文本 | Windows OCR API 或 Tesseract | P1 |
| 工具调用链记录 | 扩展现有 `AgentLoopRunResult::auditTrail` | P0 |
| 命令执行链记录 | 扩展现有命令审计日志 | P0 |
| 低风险步骤回放 | 在计划窗口中展示步骤列表，用户确认后逐一执行 | P2 |

### 5.3 暂不做

- 自动输入密码、API Key、验证码。
- 浏览器自动登录。
- 后台偷偷操作窗口。
- 对敏感窗口截图并写入日志。

### 5.4 验收标准

- 能看到当前前台窗口标题。
- 能保存截图到 Agent 工作目录。
- 操作记录不包含敏感正文。
- 回放前展示步骤列表，失败立即暂停。

## 6. V13：受控设备输入模拟

### 6.1 目标

- 在明确授权下，对测试窗口或明确目标窗口执行有限输入。

### 6.2 建议技术

| 技术 | 用途 | 优先级 |
|------|------|--------|
| Windows UI Automation | 通过控件定位，优先路径 | P0 |
| SendInput | 低级 fallback，仅用于测试窗口 | P1 |
| 前台窗口校验 | 执行前确认目标窗口 | P0 |
| 停止按钮 | 随时中止后续动作 | P0 |
| 审计日志 | 记录每次输入操作 | P0 |

### 6.3 禁止

- 自动输入密码、API Key、验证码。
- 绕过 UAC。
- 跨应用记录键盘输入。
- 对未知窗口执行点击。
- 坐标盲点点击作为主要策略。

### 6.4 验收标准

- 只在测试窗口中验证。
- 能输入普通文本。
- 能点击明确控件。
- 停止按钮可中止后续动作。

## 7. V14：个人 AI 管家能力整合

### 7.1 目标

- 把聊天、角色、文件、命令、技能、记忆和电脑感知整合成可持续使用的个人助手。

### 7.2 候选场景

- 项目检查：读取 diff → 构建 → 测试 → 总结 → 记忆。
- 文件整理：按规则分类移动文件。
- 工作日报：从 git log + 日志摘要 + 文件变更生成。
- 本地资料摘要：读取项目文档，按关键词组织。
- 长期角色提示词和角色记忆。
- 简单定时提醒。

### 7.3 暂不纳入

- 游戏逆向、DLL 注入、内存修改、绕过反作弊。

## 8. 总体推荐执行顺序

当前 V1-V10.3 全部完成，Chat/Agent 模式切换按钮已就位。更稳的下一步：

```text
1. 补完 V11-TASK-007：统一模式验证（手工验证 4 个场景）          ← 优先，刚完成的改动需要验证
2. 进入 V11-TASK-001 到 TASK-006：P0 工具开发                      ← 核心交付
3. V11-TASK-008：验收和文档                                       ← 收尾
4. 根据真实 AI 验证结果，决定 V11 P1/P2 工具是否继续
5. 进入 V12 电脑感知（不急于 V13 设备输入）
```

原因：

- 命令执行、技能流程和 Function Calling 接入已具备第一版。
- 模式切换刚落地，需要先验证再大规模铺开。
- V11 工具能在不增加安全风险的前提下提升项目实用价值。
- V12 电脑感知比 V13 设备输入风险低，先做感知层更稳健。

V12 完成后可以写：

> 实现受控电脑感知能力，包括窗口枚举、前台检测、截图保存和 OCR 识别，并通过审计日志记录完整操作链路，为用户确认回放和后续输入模拟提供安全基础。

注意：简历中始终强调"受控"、"白名单"、"可停止"、"可审计"，不要写"AI 可以任意操作电脑"或"AI 可以自动执行任意命令"。
