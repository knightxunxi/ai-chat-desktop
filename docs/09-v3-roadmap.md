# V3 Roadmap

本文档用于规划 AI Chat Desktop 的 V3 版本。V3 的重点不是继续堆聊天基础功能，而是围绕安全性、可管理性、可诊断性和可扩展性，把项目推进到更接近企业桌面应用的形态。

## 1. V3 目标

V3 重点解决四类问题：

- 安全性：减少 API Key 明文存储带来的风险。
- 会话管理：让聊天记录更容易查找、整理和导出。
- 服务商扩展：支持多个 OpenAI 兼容服务商预设和模型参数。
- 诊断体验：把日志、错误分类和重试能力做得更清楚。

## 2. 技术类型

V3 涉及的主要技术类型：

| 技术类型 | 用途 | 预期落点 |
| --- | --- | --- |
| C++17 | 主开发语言 | 核心模型、控制层、存储和服务层 |
| Qt 6 Widgets | 桌面 GUI | 设置、会话管理、日志查看、导出入口 |
| Qt Network | HTTP/S API 调用 | OpenAI 兼容聊天接口、多服务商请求 |
| Qt SQL / SQLite | 本地结构化存储 | 聊天会话、消息、会话元数据 |
| Windows Credential Manager / Win32 Credential Management API | 安全凭据存储 | API Key 安全保存 |
| QSettings | 非敏感配置 | 语言、Base URL、模型、UI 偏好 |
| JSON | 轻量配置文件 | 服务商预设、角色模板导入导出 |
| QFile / QTextStream | 文件读写 | 日志、导出 Markdown/JSON |
| CMake | 构建系统 | 模块、测试目标、发布构建 |
| CTest | 自动化测试入口 | 单元测试和 smoke test |
| Git / GitHub | 协作流程 | feature branch、PR、合并、版本记录 |
| Windows 打包 / windeployqt | 桌面发布 | Release 目录和压缩包 |

可选技术：

- UI 自动化测试工具：用于后续覆盖关键界面流程。
- Markdown 语法高亮组件或自定义渲染：用于增强代码块展示。

## 3. V3 范围

### 3.1 必做范围

- API Key 安全存储方案调研与实现。
- 会话重命名。
- 会话搜索。
- 聊天记录导出。
- 多服务商预设。
- 模型参数配置。
- 更清楚的错误分类和重试入口。
- 应用内日志查看。

### 3.2 可选范围

- Markdown 代码高亮。
- 角色提示词模板导入导出。
- 会话标签或收藏。
- UI 自动化测试。
- Release 版本号和变更日志规范化。

### 3.3 V3 暂不包含

- 云同步。
- 用户账号系统。
- 插件市场。
- 自动更新系统。
- 移动端、Web 端或 macOS/Linux 平台迁移。

当前 V3 只面向 Windows 桌面使用场景，安全凭据存储优先采用 Windows Credential Manager。后续如果需要迁移到其他平台，再单独设计平台适配层。

## 4. 推荐里程碑

### M1 安全存储

目标：

- 将 API Key 从普通本地配置迁移到更安全的系统凭据存储。

任务：

- 调研 Windows Credential Manager 与继续使用 `QSettings` 的差异。
- 设计面向 Windows Credential Manager 的 `CredentialStorage` 接口。
- 保留配置兼容迁移路径。
- 确认日志、导出和错误信息不泄露 API Key。

验收标准：

- 新保存的 API Key 不再写入普通 `QSettings`。
- 旧配置中的 API Key 可以平滑迁移或提示用户重新保存。
- 自动化测试覆盖凭据存储抽象。

### M2 会话管理增强

目标：

- 让聊天记录更容易整理和检索。

任务：

- 修复点击会话导致会话列表顺序变化的问题。
- 支持会话重命名。
- 支持会话搜索。
- 支持导出当前会话。
- 支持导出 Markdown 或 JSON。

验收标准：

- 点击会话只切换当前会话，不改变列表顺序。
- 可以手动重命名会话。
- 可以按标题或消息内容搜索会话。
- 导出文件内容完整且不包含 API Key。

### M3 服务商和模型参数

目标：

- 降低配置不同 OpenAI 兼容服务商的成本。

任务：

- 增加服务商预设，例如 DeepSeek、OpenAI、自定义。
- 设置窗口支持选择服务商。
- 支持常见模型参数，例如 temperature、max tokens。
- 请求体构建支持可选参数。

验收标准：

- 选择服务商后自动填入默认 Base URL 和推荐模型。
- 自定义服务商仍可手动配置。
- 参数为空时不影响现有请求。

### M4 错误诊断和日志查看

目标：

- 出错时用户能更快判断问题来自网络、配置、认证、额度还是服务端。

任务：

- 增加错误分类。
- 增加重试入口。
- 增加应用内日志查看窗口。
- 支持打开日志文件所在目录。

验收标准：

- 常见 HTTP 状态码有更清晰提示。
- 请求失败后可以重试。
- 用户可以在应用内查看最近日志。
- 日志仍不包含 API Key 和聊天正文。

### M5 V3 验收与发布准备

目标：

- 对 V3 做阶段性验收，并准备可发布版本。

任务：

- 编写 V3 验收记录。
- 更新 README。
- 更新 Windows 打包说明。
- 编写 Release Notes。

验收标准：

- Debug 构建通过。
- 自动化测试全部通过。
- 核心手工验收通过。
- 文档和发布说明同步。

## 5. V3 任务拆分

### V3-TASK-001 编写 V3 Roadmap

范围：

- 明确 V3 目标、范围、技术类型、里程碑和任务拆分。

验证：

- 文档合并到 `main`。

### V3-TASK-002 API Key 安全存储调研

范围：

- 比较 Windows Credential Manager 和继续使用 `QSettings` 的差异。
- 明确 Win32 Credential Management API 的读写、删除和错误处理方案。
- 形成技术方案和风险说明。

验证：

- 输出 Windows API Key 安全存储方案文档。

### V3-TASK-003 新增 CredentialStorage 抽象

范围：

- 创建凭据存储接口。
- 将 API Key 读写从 `ConfigStorage` 中拆出。
- 为自动化测试准备内存实现或 fake 实现。

验证：

- 配置保存和读取仍可用。
- 自动化测试覆盖新接口。

### V3-TASK-004 实现 API Key 安全保存

范围：

- 接入 Windows Credential Manager。
- 迁移或清理旧 `QSettings` API Key。
- CMake 在 Windows 构建中链接 `Advapi32`。

验证：

- 新保存的 API Key 不再出现在普通配置中。
- 真实 API 请求仍可用。

### V3-TASK-005 会话重命名与列表顺序修复

范围：

- 修复点击会话导致会话列表顺序变乱的问题。
- 区分“会话被访问”和“会话内容被更新”两种场景，避免普通切换触发置顶。
- 会话列表支持重命名当前会话。
- 数据库保存更新后的标题。

验证：

- 点击不同会话时，列表顺序保持不变。
- 发送新消息或真正更新会话内容时，排序规则仍符合预期。
- 重启后会话标题仍保留。

### V3-TASK-006 会话搜索

范围：

- 支持按标题和消息内容搜索。
- 搜索结果可点击进入会话。

验证：

- 多会话场景下搜索结果准确。

### V3-TASK-007 聊天记录导出

范围：

- 支持导出当前会话为 Markdown。
- 可选支持 JSON 导出。

验证：

- 导出文件包含角色、时间和消息内容。
- 导出不包含 API Key。

### V3-TASK-008 多服务商预设

范围：

- 增加服务商预设模型。
- 设置窗口支持选择预设。
- 支持自定义服务商。

验证：

- 选择 DeepSeek/OpenAI 预设后配置自动填充。

### V3-TASK-009 模型参数配置

范围：

- 增加 temperature、max tokens 等可选参数。
- 请求体构建支持这些参数。

验证：

- 参数填写后出现在请求体中。

### V3-TASK-010 错误分类和重试

范围：

范围：

## 6. 推荐执行顺序

```text
V3-TASK-001
V3-TASK-002 -> V3-TASK-003 -> V3-TASK-004
V3-TASK-005 -> V3-TASK-006 -> V3-TASK-007
V3-TASK-008 -> V3-TASK-009
V3-TASK-010 -> V3-TASK-011
V3-TASK-012
```

优先先解决安全存储，再做会话和服务商扩展。这样可以避免后续功能继续依赖普通明文 API Key 配置。

## 7. 风险点

- 当前 V3 只实现 Windows Credential Manager。未来如果迁移 macOS/Linux，需要重新设计平台适配和验收范围。
- 凭据迁移需要谨慎，避免用户已有配置丢失。
- 会话搜索如果直接扫描大量消息，后续可能需要索引优化。
- 多服务商参数差异较大，请求体构建需要保持兼容。
- 错误重试需要明确边界，避免重复发送用户不想重复的请求。
- 应用内日志查看不能暴露敏感信息。

## 8. V3 验收标准

V3 完成时应满足：

- API Key 不再使用普通 `QSettings` 明文保存。
- 会话可以重命名、搜索和导出。
- 服务商预设和模型参数配置可用。
- 常见错误有分类提示和重试入口。
- 应用内可以查看日志或打开日志目录。
- 自动化测试全部通过。
- README、打包说明和验收记录同步更新。
