# V4 Roadmap

本文档用于规划 AI Chat Desktop 的 V4 阶段。V4 不继续扩大基础聊天能力，而是优先提升工程质量、自动化验证、可维护性和后续扩展基础。

执行状态：V4-TASK-001 已完成并合并到 `main`。V4-TASK-002 和 V4-TASK-003 已完成，当前测试数量为 16 个。

## 1. V4 目标

V4 重点解决四类问题：

- 工程化：让构建、测试和代码规范更接近真实团队项目。
- 可验证性：补齐 UI smoke test、CI 和关键流程自动化验证。
- 使用体验：增强 Markdown、消息操作和角色提示词管理。
- 扩展性：为后续小工具集成预留稳定结构。

## 2. 技术类型

| 技术类型 | 用途 | 预期落点 |
| --- | --- | --- |
| GitHub Actions | CI 自动化 | PR 和 main 自动构建、测试 |
| CMake / CTest | 构建和测试入口 | Debug / Release 构建验证 |
| Qt 6 Widgets | 桌面 GUI | UI smoke test、消息体验增强 |
| Qt Test 或轻量 GUI smoke | UI 验证 | 启动、关闭、设置、日志窗口 |
| clang-format | 代码格式统一 | 后续引入格式规范 |
| Markdown 渲染增强 | 消息展示 | 代码块复制、代码高亮 |
| JSON | 导入导出 | 角色提示词模板导入导出 |
| 本地工具抽象 | 小工具集成 | JSON 格式化、Markdown 格式化等 |

## 3. V4 范围

### 3.1 必做范围

- GitHub Actions CI。
- 代码格式规范文档或 `.clang-format`。
- UI 启动/关闭 smoke test。
- Markdown 代码块复制按钮。
- 角色提示词模板导入导出。
- 小工具集成方案设计。

### 3.2 可选范围

- clang-tidy 静态检查。
- GitHub Release 自动上传构建产物。
- SQLite FTS 会话全文搜索。
- 会话标签、收藏、归档。
- 更完整的 UI 自动化测试。

### 3.3 V4 暂不包含

- 云同步。
- 用户账号系统。
- 插件市场。
- 自动更新。
- macOS/Linux 适配。

## 4. 推荐里程碑

### M1 CI 和基础工程规范

目标：

- 让 PR 和 main 分支自动执行构建和测试。
- 为后续协作和重构提供安全网。

任务：

- 新增 GitHub Actions workflow。
- 覆盖 Windows Debug 和 Release 构建。
- 自动运行 CTest。
- 补充 CI 使用说明。
- 后续引入 `.clang-format`。

验收标准：

- PR 创建后自动触发 CI。
- main 推送后自动触发 CI。
- Debug 和 Release 构建均通过。
- CTest 全部通过。

### M2 UI 自动化基础

目标：

- 补齐当前桌面应用的 UI 验证短板。

任务：

- 增加启动/关闭 smoke test。
- 验证主窗口可创建。
- 验证设置窗口、日志窗口可打开。
- 验证关闭后进程释放。

验收标准：

- UI smoke test 可在本地和 CI 运行。
- 失败时能输出可定位的信息。

### M3 消息体验增强

目标：

- 提升聊天消息可读性和可操作性。

任务：

- 代码块增加复制按钮。
- 可选增加代码高亮。
- 可选增加单条消息删除。
- 可选增加重新生成当前回复。

验收标准：

- AI 输出代码时，代码块和普通文本区分清晰。
- 用户可以复制代码块内容。
- 自动化测试覆盖至少一条 Markdown 代码块行为。

### M4 角色提示词增强

目标：

- 让角色提示词模板更便于迁移和管理。

任务：

- 支持模板导出 JSON。
- 支持模板导入 JSON。
- 导入时处理重复 ID 或重复名称。
- 支持恢复默认模板。

验收标准：

- 模板可以导出后重新导入。
- 非法 JSON 有清晰错误提示。
- 导入导出不影响当前会话。

### M5 小工具集成设计

目标：

- 为后续工具集成建立边界，不直接把工具逻辑堆进主窗口。

任务：

- 设计本地工具抽象。
- 规划工具入口 UI。
- 先实现 1-2 个本地工具，例如 JSON 格式化和 Markdown 格式化。

验收标准：

- 工具有统一入口。
- 工具逻辑与主聊天流程解耦。
- 后续新增工具不需要大幅修改主窗口。

## 5. V4 任务拆分

### V4-TASK-001 GitHub Actions CI

范围：

- 新增 `.github/workflows/ci.yml`。
- 在 pull request 和 main push 时自动触发。
- 使用 Windows runner。
- 安装 Qt 6。
- 执行 Debug 和 Release 构建。
- 执行 `ctest --output-on-failure`。

验证：

- workflow 文件语法合理。
- 本地 Debug 构建和测试通过。
- 合并后在 GitHub Actions 页面确认 CI 通过。

### V4-TASK-002 代码格式规范

范围：

- 新增 `.clang-format`。
- 说明格式化命令。
- 明确暂不强制格式化历史文件，避免大规模无关 diff。

验证：

- 新增或修改代码可按统一格式处理。

### V4-TASK-003 UI 启动/关闭 Smoke Test

范围：

- 增加自动化测试覆盖应用启动和关闭。
- 确认关闭后进程释放。

验证：

- 本地和 CI 都可以运行。

### V4-TASK-004 Markdown 代码块复制

范围：

- AI 消息代码块增加复制按钮。
- 保留原始消息复制能力。

验证：

- 代码块复制内容准确。
- 普通 Markdown 展示不回退。

### V4-TASK-005 角色提示词导入导出

范围：

- 支持导出模板 JSON。
- 支持导入模板 JSON。
- 处理非法文件和重复模板。

验证：

- 导出文件可重新导入。
- 导入后重启仍保留。

### V4-TASK-006 小工具集成方案

范围：

- 输出小工具集成设计文档。
- 明确工具抽象、UI 入口和首批工具范围。

验证：

- 方案文档合并到 main。

## 6. 推荐执行顺序

```text
V4-TASK-001
V4-TASK-002 -> V4-TASK-003
V4-TASK-004 -> V4-TASK-005
V4-TASK-006
```

优先做 CI，因为后续所有功能都需要自动构建和测试兜底。

## 7. 风险点

- GitHub Actions 的 Qt 安装耗时较长，需要启用缓存。
- Windows GUI 测试在 CI 中可能受桌面环境限制，先做轻量 smoke test。
- 自动发布 Release 包涉及产物大小和凭据权限，初期不纳入 Task1。
- Markdown 高亮如果引入第三方库，需要评估依赖体积和许可证。
- 小工具集成需要先设计边界，否则容易把主窗口继续做大。

## 8. V4 验收标准

V4 完成时应满足：

- PR 和 main push 自动构建测试。
- Debug 和 Release CI 通过。
- 代码格式规则明确。
- 至少一个 UI smoke test 覆盖关键窗口生命周期。
- Markdown 代码块复制可用。
- 角色提示词模板支持导入导出。
- 小工具集成方案明确。
