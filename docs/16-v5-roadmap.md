# V5 Roadmap

本文档用于规划 AI Chat Desktop 的 V5 阶段。V5 的重点不再继续扩展基础聊天能力，而是把 V4 中完成设计的小工具集成方案落地，并补强会话组织、测试覆盖和项目展示质量。

执行状态：V5-TASK-001 至 V5-TASK-008 已完成。当前 V5 已实现本地工具系统、首批文本工具、工具窗口、会话收藏/归档/筛选和验收文档，当前测试数量为 20 个。

## 1. V5 目标

V5 重点解决四类问题：

- 工具扩展：实现内置本地小工具，让应用从“单一聊天窗口”扩展为“聊天 + 辅助处理”的桌面工具。
- 体验增强：减少重复手工整理文本、JSON、Markdown 的操作，提高日常使用效率。
- 架构边界：把工具逻辑与主聊天流程解耦，避免继续扩大 `MainWindow` 的职责。
- 项目展示：让项目在简历中体现抽象设计、输入校验、自动化测试和迭代交付能力。

## 2. 技术类型

| 技术类型 | 用途 | 预期落点 |
| --- | --- | --- |
| C++17 抽象接口 | 统一本地工具调用方式 | `LocalTool` / `ToolResult` |
| Qt 6 Widgets | 工具窗口和主窗口入口 | `ToolsDialog`、工具按钮 |
| Qt JSON | JSON 解析、格式化、压缩 | `QJsonDocument` / `QJsonParseError` |
| 文本处理算法 | Markdown、普通文本清理 | 空白字符、换行、代码块保护 |
| CMake / CTest | 工具逻辑测试入口 | `JsonFormatToolTest`、`MarkdownFormatToolTest` |
| UI smoke test | 验证工具窗口基础交互 | 打开工具窗口、运行工具、关闭窗口 |
| GitHub Actions | 持续集成质量门禁 | Windows Debug / Release 构建和测试 |
| SQLite / FTS 可选 | 会话搜索和组织 | 会话标签、收藏、归档、全文搜索 |

## 3. V5 范围

### 3.1 必做范围

- 新增本地工具抽象接口。
- 实现 JSON 格式化工具。
- 实现 JSON 压缩工具。
- 新增工具窗口 `ToolsDialog`。
- 主窗口增加工具入口。
- 工具输出支持复制。
- 工具输出支持插入到当前聊天输入框，但不自动发送。
- 增加工具逻辑单元测试。
- 更新 README 和学习文档。

### 3.2 建议范围

- Markdown 简单整理工具。
- 普通文本清理工具。
- 工具窗口 smoke test。
- 会话标签、收藏、归档的设计和第一版实现。
- 会话列表搜索或过滤。

### 3.3 可选范围

- Markdown 代码高亮增强。
- SQLite FTS 会话全文搜索。
- GitHub Release 构建产物上传。
- clang-tidy 静态检查。
- 更完整的 UI 自动化测试。

### 3.4 V5 暂不包含

- 插件市场。
- 第三方脚本运行。
- AI 自动调用工具。
- 网络工具调用。
- 用户自定义代码执行。
- 跨进程工具沙箱。
- 云同步。
- 用户账号系统。
- 自动更新。
- macOS/Linux 迁移。

## 4. 推荐里程碑

### M1 本地工具抽象

目标：

- 建立工具系统边界，让后续新增工具不依赖主窗口细节。

任务：

- 新增 `src/tools/` 目录。
- 新增 `ToolResult` 结果结构。
- 新增 `LocalTool` 抽象接口。
- 在 CMake 中加入工具模块。

验收标准：

- 工具逻辑可以脱离 UI 单独调用。
- 新增工具不需要修改聊天发送流程。
- 编译通过。

### M2 JSON 工具

目标：

- 完成首批低风险、高频使用的小工具。

任务：

- 实现 JSON 格式化。
- 实现 JSON 压缩。
- 处理非法 JSON 输入。
- 增加 JSON 工具单元测试。

验收标准：

- 合法 JSON 可以输出格式化或压缩结果。
- 非法 JSON 有明确错误提示。
- 测试覆盖合法输入、非法输入和空输入。

### M3 工具窗口

目标：

- 让用户可以在应用内使用本地工具。

任务：

- 新增 `ToolsDialog`。
- 支持工具选择。
- 支持输入区和输出区。
- 支持运行、复制输出、插入到聊天输入框、关闭。
- 主窗口增加“工具”入口。

验收标准：

- 工具窗口可以从主窗口打开。
- 切换工具后说明文本正确更新。
- 输出可以复制。
- 输出可以插入聊天输入框，但不会自动发送。

### M4 Markdown 和文本工具

目标：

- 提供更贴近日常写作和聊天整理的文本处理能力。

任务：

- 实现 Markdown 简单整理。
- 整理多余空行和行尾空格。
- 保留 Markdown 代码块内部内容。
- 实现普通文本清理。
- 增加对应单元测试。

验收标准：

- Markdown 整理不会破坏代码块。
- 文本清理可以统一换行和删除多余空白。
- 测试覆盖代码块、普通段落和空输入。

### M5 会话组织增强

目标：

- 提高多会话场景下的检索和管理能力。

任务：

- 先输出会话组织设计说明。
- 评估会话标签、收藏、归档、搜索的优先级。
- 优先实现低风险功能，例如收藏或归档。
- 如实现搜索，优先使用现有存储结构；必要时再评估 SQLite FTS。

验收标准：

- 会话操作不会改变原有会话顺序。
- 当前会话选中状态稳定。
- 新增状态重启后仍然保留。
- 有对应测试或明确手工验证步骤。

### M6 发布质量增强

目标：

- 让项目更接近可展示、可下载、可复盘的个人作品。

任务：

- 补充 V5 验收记录。
- 更新学习文档和简历问答资料。
- 可选增加 Release 构建产物上传。
- 可选补充 clang-tidy 或更多静态检查。

验收标准：

- README 能说明当前能力和构建方式。
- 文档能体现需求、设计、实现、测试、复盘流程。
- CI 继续通过。

## 6. 推荐执行顺序

```text
V5-TASK-001
-> V5-TASK-002
-> V5-TASK-003
-> V5-TASK-004
-> V5-TASK-005
-> V5-TASK-006
-> V5-TASK-007
-> V5-TASK-008
```

优先做工具抽象和 JSON 工具，因为它们风险低、边界清晰，适合作为 V5 的第一批可验证功能。

会话组织增强放在工具系统之后，因为它涉及存储结构和 UI 状态，改动风险高于纯文本工具。

## 7. 风险点

- 工具窗口如果直接操作主窗口内部控件，会让 UI 耦合变重；应通过信号或回调传递输出。
- Markdown 整理如果直接按字符串替换，可能破坏代码块；需要先识别代码块范围。
- JSON 工具错误信息如果只返回“失败”，定位价值不够；应保留解析错误位置。
- 会话标签、收藏、归档会影响存储结构，需要兼容旧数据。
- UI smoke test 在 CI 中容易受窗口焦点影响，应保持测试动作简单。
- 工具输出不应自动发送给 AI，避免用户未确认内容就消耗 API 调用。

## 8. V5 验收标准

V5 完成时应满足：

- 本地工具抽象完成，工具逻辑与聊天流程解耦。
- JSON 格式化和 JSON 压缩可用。
- 工具窗口可以从主窗口打开。
- 工具输出可以复制，也可以插入当前聊天输入框。
- Markdown 或普通文本清理至少完成一个。
- 新增工具逻辑测试通过。
- UI smoke test 覆盖工具窗口基础生命周期。
- 会话组织增强至少完成设计；如进入实现，则必须保证会话顺序稳定。
- README、学习文档和验收记录同步更新。
- 本地 CTest 和 GitHub Actions 通过。

## 9. 简历表达方向

V5 完成后可以考虑这样描述：

> 在 C++/Qt 桌面聊天应用中设计本地工具扩展接口，将 JSON 格式化、Markdown 整理等文本处理逻辑与主聊天流程解耦；通过结构化返回值处理输入校验和错误提示，并使用 CTest 和 GitHub Actions 覆盖工具逻辑与窗口基础交互。

这个表达重点放在“抽象接口、解耦、输入校验、自动化测试”，比单纯写“集成小工具”更能体现工程能力。

## 10. 后续阶段初步规划

本节只记录后续方向，不作为 V5 的详细任务范围。等 V5 完成后，再为下一阶段单独编写 Roadmap。

### V6 受控本地交互工具

目标：

- 让应用具备有限、可确认、可记录的电脑交互能力。
- 先实现“用户主动触发的工具”，不直接进入自动 Agent 执行循环。

候选能力：

- 读取用户指定文件。
- 列出用户指定文件夹。
- 保存聊天输出到本地文件。
- 打开本地文件或外部链接。
- 对指定文件内容生成摘要。
- 将工具执行结果插入聊天输入框。

关键边界：

- 每次文件操作都需要用户确认。
- 默认只访问用户明确选择的路径。
- 删除、覆盖、执行程序等高风险操作默认不做。
- 所有本地交互操作写入日志。
- 工具失败不能影响聊天主流程。

### V7 Agent 执行循环雏形

目标：

- 在 V6 的受控工具基础上，引入简单的任务规划和多步执行。
- AI 可以根据用户目标选择工具，但每一步执行前仍保留用户确认。

候选能力：

- 任务拆解。
- 工具选择。
- 执行前确认。
- 执行结果回传给 AI。
- 多轮继续执行。
- 用户中断任务。

示例流程：

```text
用户目标
-> AI 拆解任务
-> 选择本地工具
-> 用户确认
-> 执行工具
-> 读取执行结果
-> AI 判断是否继续
```

关键边界：

- Agent 不应绕过用户确认直接操作文件系统。
- 每一步都需要可追踪的执行日志。
- 必须支持停止任务。
- 失败时需要展示失败原因和当前进度。

### V8 权限、安全和自动化工作流增强

目标：

- 在 Agent 雏形稳定后，再考虑更复杂的权限模型和自动化流程。

候选能力：

- 工作区权限配置。
- 工具权限分级。
- 高风险操作二次确认。
- 任务执行历史。
- 常用工作流模板。
- 更完整的错误恢复策略。

暂不进入的方向：

- 插件市场。
- 任意脚本执行。
- 后台无人值守自动化。
- 跨设备同步。
- 系统级全盘扫描。

## 11. 阶段关系

推荐路线：

```text
V5：本地工具系统
-> V6：受控文件/系统交互工具
-> V7：Agent 执行循环雏形
-> V8：权限、安全和自动化工作流增强
```

其中 V5 的 `LocalTool` 抽象是后续 Agent 能力的基础。先把工具调用、输入输出、错误返回、日志记录和测试边界做好，再进入电脑交互和 Agent 执行循环，会比直接做完整 Agent 更可控。
