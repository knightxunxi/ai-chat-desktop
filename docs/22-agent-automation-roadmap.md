# Agent 与电脑交互后续规划

本文档回答后续阶段中“什么时候让 AI 分析、拆解并执行命令，以及什么时候记录人的操作习惯、模拟设备输入”的问题。

核心结论：

- V7：让 AI 分析目标、拆解任务、建议工具，但不直接执行系统命令。
- V8：进入受控命令执行，只允许用户确认后的白名单命令。
- V9：进入操作记录和可确认回放，先记录应用内工具步骤。
- V10：再考虑键盘、鼠标或设备输入模拟，必须有明确权限、停止按钮和审计日志。

## 1. 为什么不能直接做

命令执行和设备输入模拟属于高风险能力。它们可能影响文件、进程、系统设置、账号登录状态和用户隐私。如果在文件工具边界还不稳定时直接加入，会导致三个问题：

- 安全边界不清楚：AI 可能请求执行超出预期的操作。
- 调试困难：失败原因可能来自命令、权限、窗口焦点或系统状态。
- 简历表达风险：如果没有权限模型和测试，只写“实现 Agent 控制电脑”容易被追问到无法自洽。

因此推荐先完成 V6 的受控文件工具，再分阶段扩展。

## 2. V7：AI 分析与任务拆解

目标：

- AI 根据用户目标拆解任务。
- AI 选择已有工具。
- UI 展示待执行步骤。
- 用户逐步确认。

示例流程：

```text
用户目标
-> AI 拆解任务
-> AI 建议使用文件读取/目录列出/文本工具
-> 用户确认
-> 工具执行
-> 执行结果回传给 AI
-> AI 给出下一步建议
```

V7 不包含：

- Shell 命令执行。
- 自动键鼠操作。
- 后台无人值守执行。

## 3. V8：受控命令执行

这是“让她分析、拆解，并执行命令”的合适阶段。

前提：

- V6 文件工具稳定。
- V7 工具建议和用户确认流程稳定。
- 日志能记录每一步操作。
- UI 有任务中止入口。

建议能力：

- 命令白名单，例如 `dir`、`git status`、`git diff --check`、`ctest`。
- 固定工作目录，优先限制在项目目录。
- 命令参数模板化，避免拼接任意字符串。
- 执行前展示命令、工作目录和影响范围。
- 执行后记录退出码、标准输出摘要和错误摘要。
- 设置超时，避免命令长期占用。

禁止能力：

- 任意 PowerShell / CMD 字符串执行。
- 删除、格式化、注册表修改、系统服务修改。
- 静默安装软件。
- 后台自动执行命令。
- 读取或打印 API Key、密码、Token。

## 4. V9：操作记录与回放

这是“模拟人的操作习惯进行记录”的合适阶段，但第一版只建议记录应用内操作和工具步骤。

建议记录：

- 用户目标。
- AI 拆解步骤。
- 用户确认过的工具调用。
- 命令白名单调用。
- 文件工具结果摘要。
- 每一步耗时和失败原因。

建议回放：

- 只能回放已确认的低风险步骤。
- 回放前展示步骤列表。
- 用户可跳过某一步。
- 遇到失败立即暂停。

暂不建议记录：

- 全局键盘输入。
- 密码框内容。
- 浏览器登录态细节。
- 未授权窗口内容。

## 5. V10：设备输入模拟

这是“模拟设备输入”的合适阶段。

可选实现方向：

- Windows UI Automation：优先按控件查找和点击，稳定性高于坐标点击。
- 键盘/鼠标事件模拟：只作为低级 fallback。
- 窗口前台校验：确认当前操作窗口符合预期。
- 显式停止按钮：任何时候都能停止自动化。
- 执行前确认：展示将要点击、输入或等待的步骤。

安全边界：

- 不自动输入密码、API Key、验证码。
- 不绕过系统权限提示。
- 不在后台偷偷操作。
- 不跨应用记录敏感输入。
- 不把屏幕内容或输入内容写入日志。

## 6. 推荐阶段关系

```text
V6：受控文件/目录工具
-> V7：AI 拆解任务并建议工具
-> V8：受控命令执行
-> V9：操作记录和确认回放
-> V10：设备输入模拟
```

这条路线的重点是：先让 AI 学会“建议”，再让系统具备“受控执行”，最后才进入“模拟操作”。这样实现难度、权限风险和测试压力都会更可控。
