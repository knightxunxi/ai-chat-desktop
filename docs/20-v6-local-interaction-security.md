# V6 本地交互安全设计

本文档记录 AI Chat Desktop V6 阶段的本地文件/系统交互边界。V6 的目标不是做完整 Agent，而是先建立“用户主动触发、路径来源明确、操作可记录”的低风险本地工具能力。

执行状态：V6 安全边界已用于当前开发分支实现。

## 1. 设计原则

- 用户显式选择：文件和目录路径必须来自 `QFileDialog`，不提供自由路径输入框。
- 最小能力集合：只做读取、列目录、保存输出、打开路径，不做删除、移动、脚本执行。
- 执行前可见：打开文件或文件夹前展示目标路径，由用户确认。
- 输出不自动发送：文件内容或目录列表只进入工具输出区，用户可复制或插入聊天输入框，但不会自动调用 AI。
- 日志可诊断但不泄密：记录操作类型、成功/失败、输出长度和路径摘要，不记录文件正文、完整目录和 API Key。

## 2. 允许操作

| 操作 | 触发方式 | 限制 |
| --- | --- | --- |
| 读取文本文件 | 用户选择文件 | 默认最大 1 MiB，检测二进制内容 |
| 列出文件夹 | 用户选择目录 | 默认最多展示 200 个条目 |
| 保存工具输出 | 用户选择保存路径 | 已存在文件必须二次确认 |
| 打开文件或文件夹 | 用户选择路径并确认 | 只允许已存在的文件或目录 |

## 3. 禁止操作

V6 明确不做：

- 删除文件或目录。
- 移动、重命名或批量覆盖文件。
- 执行脚本、程序、Shell 命令或 PowerShell 命令。
- 后台无人值守任务。
- 系统级全盘扫描。
- 自动读取未由用户选择的路径。
- 自动把文件内容发送给 AI。
- 在日志中记录文件正文、聊天正文、API Key 或完整目录。

## 4. 路径来源和校验

路径来源：

- 读取文件：`QFileDialog::getOpenFileName`。
- 列出目录：`QFileDialog::getExistingDirectory`。
- 保存输出：`QFileDialog::getSaveFileName`。
- 打开路径：文件或目录选择框。

校验策略：

- 空路径直接返回错误。
- 读取文件时必须是存在的普通文件。
- 列目录时必须是存在的目录。
- 打开路径时必须是存在的文件或目录。
- 保存时自动创建父目录，但不允许静默覆盖已有文件。

## 5. 日志策略

日志模块记录：

- 操作名称，例如 `read_text_file`、`list_directory`、`save_text_file`。
- 成功或失败。
- 错误原因。
- 输出长度。
- 路径摘要。

路径摘要格式：

```text
name=<文件名> dirHash=<目录哈希前 12 位>
```

这样能定位“哪个文件名和哪个目录范围”，同时避免直接暴露完整用户目录。

## 6. 错误处理

V6 需要明确提示以下情况：

- 文件不存在。
- 路径类型不符合要求。
- 文件过大。
- 文件疑似二进制。
- 文件打开失败。
- 父目录创建失败。
- 写入失败。
- 已存在文件未确认覆盖。

错误通过 `ToolResult` 返回给 UI，UI 只负责展示，不解析异常字符串。

## 7. 测试边界

自动化测试覆盖：

- 文本文件读取。
- 二进制文件拒绝。
- 大文件拒绝。
- 目录列出。
- 保存新文件。
- 拒绝未确认覆盖。
- 允许确认后覆盖。
- 打开路径前校验。
- 日志不包含文件正文。
- 文件工具窗口基础控件和初始状态。

手工验证覆盖：

- 文件选择框可用。
- 保存已有文件时有二次确认。
- 打开文件或目录前有确认。
- 工具输出可复制或插入聊天输入框。

## 8. 与后续 Agent 的关系

V6 是 Agent 能力的前置基础，但不包含自动 Agent。

后续如果进入 Agent，应继续遵守：

- AI 只能建议工具和参数。
- 用户确认后才能执行。
- 每一步都有日志。
- 用户可以中断任务。
- 高风险能力要有单独权限模型。
